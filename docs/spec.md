# dew 仕様書

コンテナ内の画像・動画と、プログラムの描画ウィンドウを、Windows のブラウザで確認するツール。

- 原本: claude.ai 上の仕様書ドキュメント(この Markdown はその書き出し)
- 最終更新: 2026-10-21(追加機能のシェル連携・外部ツール連携・ドキュメントウィンドウ・CSV・Markdown を 13〜17 章に加え、フェーズ5〜7を足した。ADR 0022)

---

## 1. 背景と目的

コンテナ内で Web サーバを立て、Windows のブラウザで見る。ブラウザは動画を自前でハードウェアデコードし音声も鳴らすので、端末描画の制約(音声なし・低 fps)はなくなる。既存ツールは「ファイル閲覧」と「GUI ウィンドウ転送」を別々に満たすが、両方を開発ワークフローに統合したものはないため自作する。

**現状の構成**

- クライアント: Windows + WezTerm(実行先はリモートの Ubuntu サーバ、WSL2、それぞれの中の Docker コンテナのいずれも対象)
- 接続: ssh → Ubuntu サーバ → `docker exec` でコンテナへ
- 作業: コンテナ内でコード編集・実行
- 見たいもの: プログラムが生成した画像・動画、アセット動画、実行時の描画ウィンドウ

**現状の課題(yazi + mpv)**

- 音声が出ない(端末経由の描画には音声経路がない)
- フレームレートが低くカクつく(端末のグラフィックプロトコルで毎フレーム画像を送るため)

**ゴール**

1. 保存済みの画像・動画を、音声付き・滑らかに、少ない手間で確認できる
2. プログラム実行時の描画ウィンドウ(cv2.imshow、matplotlib、pygame など)をブラウザでリアルタイムに見られる。プログラムは一切書き換えない

## 2. 接続方式

WSL2 と WSL2 内コンテナは Windows から `localhost` でそのまま開ける。リモートサーバでは、Windows 側の設定なしに `ssh -L` をサーバ側から自動で張ることはできないため、既定は「直結モード(トークン付き URL)」とし、ssh -L は任意の選択肢として残す。

### 2.1 実行場所ごとの届け方

| 実行場所 | Windows からの開き方 | Windows 側の設定 | セキュアコンテキスト |
| --- | --- | --- | --- |
| WSL2 | `https://localhost:8765`(WSL2 の localhost 転送 / mirrored モード) | 不要 | あり |
| WSL2 内のコンテナ | 同上。コンテナは `-p 8765:8765` か `--network host` で公開 | 不要 | あり |
| リモートサーバ(直結モード、既定) | `https://<サーバ名>:8765/?token=…` | 不要 | あり(自己署名証明書。初回のみ警告を許可) |
| リモートサーバ(ssh -L) | `https://localhost:8765` | ssh の転送指定が必要 | あり |
| リモートのコンテナ | 上の2つと同じ。コンテナのポート公開が前提 | 同上 | 同上 |

### 2.2 起動時の振る舞い

1. 実行環境(WSL2 / コンテナ / 通常の Linux)に関係なく同じ動作にする
2. 端末に URL を OSC 8 ハイパーリンクで表示する。WezTerm 上でクリックすれば開ける(ユーザー操作はこの1回だけ)
3. ブラウザのタブが既に接続中なら、新しいタブは開かず既存タブに表示を送る(F10)。タブがないときは、WezTerm に Windows の既定ブラウザで開かせる(14.3)

### 2.3 セキュアコンテキストが必要な理由

ライブ描画の低遅延デコードに使う WebCodecs と、ブラウザのショートカットを奪うための Keyboard Lock は、HTTPS か localhost でしか使えない。そのため直結モードは HTTPS で提供する。証明書が使えない環境では、平文 HTTP + Media Source Extensions(遅延は大きめ)にフォールバックする。

### 2.4 直結モードの安全策

- ランダムなトークンを発行し、URL で一度渡したら Cookie に移す(Jupyter と同じ方式)。トークンは保存してサーバを再起動しても使い続け、`dew rotate-token` で作り直す(14.2)
- 待ち受けアドレスとポートは設定可能。既定は全インターフェイスだが、`--bind 127.0.0.1` で ssh -L 専用にできる
- `--root` 指定時はその範囲外へのパス参照を禁止。ファイルは読み取り専用

### 2.5 複数ユーザー・複数コンテナでの運用

想定サーバは複数ユーザーが使い、コンテナも複数開かれる。ポートはコンテナごとに分け、トークンで他人のアクセスを防ぐ。

- コンテナ内の待ち受けポートは常に 8765(`--port` / `DEW_PORT` で変更可)
- ホスト側のポートはコンテナ作成時に各自で割り当てる。例: `docker run -p 18765:8765 -e DEW_PUBLIC_PORT=18765 …`(Jupyter の `-p 8888:8888` と同じ設定)
- コンテナ内からはホスト側のポート番号とホスト名が分からないため、表示する URL には `DEW_PUBLIC_HOST` / `DEW_PUBLIC_PORT` を使う。未設定なら警告を出し、内部ポートで表示する
- `--network host` のコンテナでは、8765 から順に空きポートを探して使い、そのまま表示する。前回のポートが空いていれば、それを使い直す(13.6)
- 1つのコンテナ内では1ユーザー1サーバ。2回目以降の `dew` は起動中のサーバ(`~/.cache/dew/server.json` にポートとトークンを記録)を再利用する
- 仮想ディスプレイ番号も空きを自動で選ぶ(`:100` から順に。前回の番号が空いていれば使い直す。13.6)
- トークンはインスタンスごとに保存し、再起動しても変えない(`dew rotate-token` で作り直す。14.2)。他ユーザーのコンテナの URL を知っていても、トークンなしでは開けない

### 2.6 ブラウザで再生できる形式(Windows 版 Chrome / Edge)

| 種別 | そのまま再生 | サーバで変換 |
| --- | --- | --- |
| 動画コーデック | H.264, VP8/VP9, AV1(HEVC は GPU 次第) | MPEG-4 Part2, ProRes, MJPEG, 非圧縮 ほか |
| コンテナ形式 | MP4, WebM(MKV は中身次第) | AVI, MOV(中身次第), FLV ほか |
| 音声 | AAC, Opus, MP3, Vorbis, FLAC | AC-3, 一部の PCM ほか |
| 画像 | PNG, JPEG, WebP, GIF, AVIF, SVG | TIFF, 16bit PNG の正確表示 |

OpenCV の `VideoWriter` 既定の `mp4v` はブラウザで再生できないため、変換対象になる。

## 3. 要件

コマンド名 `dew`。1コマンド・1ポートで、ファイル閲覧と、プログラムを書き換えないライブ描画の両方を提供する。

### 3.1 CLI

| コマンド | 動作 |
| --- | --- |
| `dew` | サーバを起動(起動済みなら再利用)し、Home を開く |
| `dew <ファイル>` | そのファイルを描画・再生する |
| `dew <ディレクトリ>` | そのディレクトリで Home を開く |
| `dew run <コマンド>` | 仮想ディスプレイと音声を用意してコマンドを実行し、ライブ描画に出す |
| `dew run --exact <コマンド>` | 上に加え、cv2.imshow を精度モード(L3)で表示 |
| `dew env` | `DISPLAY` 等の環境変数を出力(`eval "$(dew env)"` で以降のコマンドを全部ライブ描画へ) |
| `dew activate` / `dew deactivate` | 以降の GUI 実行をすべてライブ描画へ出す / 元に戻す(シェル関数が必要。13章) |
| `dew shell-init <bash\|zsh>` | シェル関数のコードを出力(13.2) |
| `dew setup-shell` | rc ファイルに `dew shell-init` の1行を追記(確認あり。13.2) |
| `dew status` | URL・接続中のタブ数・ライブウィンドウ数を表示 |
| `dew url` | URL を再表示 |
| `dew url --open` / `dew url --copy` | 端末からブラウザに Home を開かせる / OSC 52 で URL をコピー(14.6) |
| `dew setup-wezterm` | 端末からブラウザを開くための WezTerm の設定を表示(14.3) |
| `dew rotate-token` | トークンを作り直す(14.6) |
| `dew stop` | サーバを停止(activate 中のシェルがあれば確認。`--force` で確認なし。13.6) |
| `dew doctor` | 依存(ffmpeg、Xvfb、音声サーバ、GPU)を確認し、足りなければ導入コマンドを表示 |
| `dew update` | 新しいバージョンを取得して自分自身を置き換える |
| `dew --version` | バージョンとビルド日時を表示 |

### 3.2 機能要件: ファイルビューア

| ID | 要件 |
| --- | --- |
| F1 | yazi 風のディレクトリ閲覧(親・現在・プレビューの3カラム)、画像・動画はサムネイル |
| F2 | 動画を音声付き・元の fps で再生(ブラウザネイティブ再生) |
| F3 | 非対応形式は ffmpeg で H.264/AAC にオンザフライ変換、結果をキャッシュ |
| F4 | ディレクトリ監視で新規・更新ファイルを即時反映、「最新を自動で開く」モード |
| F5 | YouTube 風シークバー(ホバーでサムネイル)、コマ送り・戻し、速度変更、A-B ループ、フレーム番号 / 時刻表示 |
| F6 | すべてキーボードで操作できる(マウスも可) |
| F7 | 2ファイル以上の比較(同期再生、スライダー比較、差分表示) |
| F8 | 画像ズーム(等倍・補間なし)、ピクセル値表示 |
| F10 | 端末から開く: `dew <ファイル>` で、接続中のブラウザタブに表示を送る(yazi の opener に登録可能) |
| F11 | CSV / TSV を表として表示。大きなファイルはサーバ側(DuckDB)で全件ソート・フィルター(16章) |
| F12 | Markdown を描画し、vimium 風のキー操作で読む(17章) |
| F13 | ドキュメントウィンドウ: CSV と Markdown を表示する、キャンバスの読み取り専用のウィンドウ種別(15章) |

### 3.3 機能要件: ライブ描画(プログラムは無改変)

| ID | 要件 |
| --- | --- |
| L1 | `dew run` / `dew env` 経由で起動した任意の X11 GUI アプリ(cv2.imshow, matplotlib, pygame, Open3D, Qt 等)をブラウザに表示 |
| L2 | アプリのウィンドウごとに、キャンバス上の別々のフローティングウィンドウとして表示 |
| L3 | 精度モード(任意、`dew run --exact`): cv2.imshow / waitKey を環境変数経由で自動フックし、圧縮前の元フレームを送る。コード変更なし |
| L4 | 画面描画を H.264 で 60fps まで低遅延配信 |
| L5 | アプリの音声を Opus で配信し、映像と同期 |
| L6 | 入力パススルー: 選んだウィンドウにキーボード・マウス入力を送る(専用モードで切替。5章) |
| L7 | ライブ表示の録画(MP4 保存、再エンコードなし)と、直近 N 秒の一時停止・巻き戻し |

L3 の自動フックは、`dew run` が `PYTHONPATH` に `sitecustomize` を差し込むことで実現する(既存の sitecustomize があれば連鎖して読み込む)。matplotlib は精度モードの対象外とし、通常のウィンドウキャプチャで表示する(ツールバーの拡大・移動がそのまま使えるため)。ユーザーのコードは一切変えない。

### 3.4 非機能要件

- 遅延: 150 ms 以下(LAN / WSL2 前提)
- 性能: 想定解像度は 1600x900〜1920x1080。1080p 60fps をソフトウェアエンコードで維持、NVENC があれば使用
- 配置: 単一の静的バイナリ(フロントエンド同梱)。外部依存は ffmpeg と Xvfb、PipeWire または PulseAudio
- 対応環境: Ubuntu サーバ、WSL2、それらの中の Docker コンテナ。複数ユーザー・複数コンテナの同時利用
- クライアント: Windows の Chrome / Edge / Firefox 系(Zen など)の最新版。インストールも設定も不要。ただし Firefox 系は Keyboard Lock API がないため、入力モードで Ctrl+W などのブラウザ予約キーは送れない
- 見た目: Material Design 3、ライト / ダーク両対応
- UI の言語: 日本語

## 4. 画面仕様

画面は Home とキャンバスの2つだけ。ファイルの再生ウィンドウもライブ描画のウィンドウも、同じキャンバス上のフローティングウィンドウとして扱い、操作体系を1つにそろえる。

キーボードだけで全操作ができることに加え、文字入力(絞り込みの文字列)以外のすべての操作をマウスでも行えるようにする。ドラッグで直観的にできる操作(ウィンドウの並べ替え・移動・大きさ変更)はドラッグで行う。重ねて出す画面(ヒント、キー一覧、操作パネル、履歴ウィンドウ、確認ダイアログ)にはすべて閉じるボタンを付ける。

### 4.1 Home(引数なし起動時)

- yazi と同じ3カラム: 左に親ディレクトリ、中央に現在のディレクトリ、右にプレビュー(画像・動画のサムネイル、動画は無音のループプレビュー、メタ情報)
- 上部にパンくずリスト、現在位置からの相対パスを常時表示
- 中央カラムはリスト / グリッド表示を切替。新規・更新ファイルにはバッジ。読めないファイルは鍵アイコン
- 右下に FAB(Floating Action Button): ライブ描画キャンバスへ切替。稼働中のライブウィンドウ数をバッジで表示
- 上部のバーの左端(パンくずの左)に「キャンバスへ」ボタン(キャンバスの Home ボタンと同じ位置)。右側は左から 絞り込み、履歴、リスト / グリッド、キー一覧、操作パネル、サーバの停止(確認ダイアログを出す)
- パンくずでは初期位置のディレクトリに下線を付ける
- 複数選択: キーは Space、マウスは Shift+クリック(今の位置からクリックした位置まで)と Ctrl+クリック(1つずつ加える / 外す)。選択はフルパスで持ち、別のディレクトリへ移っても残る。選択中はバーに件数を出し、2つ以上なら「比較」ボタンも出す。Esc で選択と絞り込みを解除する
- パンくずで閲覧範囲の外のディレクトリを押したときは、閲覧範囲外のメッセージを出し、表示は今のディレクトリのままにする
- Enter で開いたファイルはキャンバスに新しいウィンドウとして追加され、画面はキャンバスへ移る
- Home は離れたときの状態(ディレクトリ、選択中のファイル、絞り込み、表示形式)を保ち、キャンバスから戻ったときにそのまま再表示する。開きたいファイルは1つのディレクトリにまとまっていることが多いため
- 初期位置は、最初に `dew` を起動したディレクトリ(7.2)

### 4.2 キャンバス(ファイル再生 + ライブ描画)

- 画面全体の大きな作業領域に、フローティングウィンドウを並べる
- 左上に Home へ戻るボタン。バーの右側は左から 全体のミュート(`M`、7.6)、同期再生(`s`)、タイル配置 / 自由配置の切替、履歴、キー一覧、操作パネル、サーバの停止。同期再生とタイル配置 / 自由配置のボタンはウィンドウが2つ以上のときだけ出す。同期再生中は「同期再生中」の印を出す
- 同期再生は、フォーカス中のウィンドウを基準に、ほかの動画の再生・停止・シーク・速度を合わせる。小さなずれは再生速度の微調整で吸収し、0.5 秒を超えるずれはシークで合わせる
- ウィンドウ一覧(タブバー)は Windows のタスクバーに見立てる。番号付きで全ウィンドウを並べ、クリックで選択する。最小化したウィンドウはタブバーで選ぶと再表示する。フォーカス中のウィンドウのタブを押すと最小化する
- タブバーの形は設定で切り替える: 上部に横並び(既定)/ 左端に縦並びで普段は隠し、画面の左端にマウスを寄せると出る(Zen・Arc の垂直タブに近い形)。設定はブラウザごとに覚える
- ウィンドウが1つなら自動で最大化。2つ以上ならタイル配置(左右・グリッド)と自由配置を切替
- フォーカス中のウィンドウは MD3 の primary 色の枠で示す。複数選択中のウィンドウは tertiary 色の枠とチェックで示す。タイル配置ではフォーカスで変えるのは枠の色だけにし、影と重なり順を変えるのは自由配置と最大化のときだけにする(Firefox 系で GPU 合成の動画が黒くなることがあったため)
- 各ウィンドウ: タイトルバー(選択のチェックボックス、番号、種別アイコン、ファイル名 / アプリのウィンドウ名、最小化・最大化・閉じるボタン)、本体、下部に YouTube 風コントロール(シークバー、時刻、再生ボタン群、速度、音量、等倍・全画面)
- 再生ボタン群は中央に `[コマ戻り][5秒戻り][30秒戻り][再生 / 停止][30秒送り][5秒送り][コマ送り]` の順でアイコンを並べる。再生 / 停止は状態に合わせてアイコンを切り替え、ほかより大きくする。アイコンは Material Symbols の replay_5 / replay_30 / forward_30 / forward_5 と skip_previous / skip_next。再生速度の表示は押すと速度の一覧を出す。コマ戻り / コマ送りは使える一時停止中だけ出す
- フォーカス中のウィンドウでは、動画の表示部分のクリックで再生 / 一時停止を切り替える(フォーカスしていないウィンドウでは、最初のクリックはフォーカスだけ)
- 最大化・最小化は Windows のウィンドウと同じ: 最大化はキャンバス全体に広げ、もう一度押すと元の位置と大きさに戻す。タイトルバーのダブルクリックでも切り替える。最小化したウィンドウは配置から外れ、タブバーにだけ残る
- タイトルバーのドラッグ: タイル配置では並び順を入れ替え(番号も変わる)、自由配置では移動する。自由配置では右下の角のドラッグで大きさを変える
- ライブウィンドウ(L1、L2): アプリが仮想ディスプレイにトップレベルのウィンドウを開くと、キャンバスに自動で追加してフォーカスする(Home にいればキャンバスへ切り替える)。名前と大きさはアプリに合わせて変わる。タイトルバーの最小化ボタンの左に、録画ボタン、入力モードのボタンの順に置く。下部は動画のウィンドウのコントロールと同じ並びにする。ライブ中はすっきりさせ、左に「ライブ」の印と大きさ、中央に大きな一時停止ボタン、右に個別のミュート・音量・等倍 / フィット・全画面だけを出す。一時停止すると巻き戻し(直近 30 秒)に入り、動画と同じシークバー(直近 30 秒のバッファ)、コマ送り・5 秒・30 秒の戻り / 送り、何秒前か、「ライブへ戻る」を出す(L7、ADR 0016)。録画中は枠を赤くし、下部に「録画中」と出す。アプリが閉じたウィンドウは最後のフレームを残し「終了」と出す
- 入力モード中のライブウィンドウは tertiary 色の枠と入力モードのボタンにし、「入力モード: … Ctrl+] で抜ける」を下部のバーに常に出す(映像に重ねると、その下をアプリで選べなくなるため)
- `dew <ファイル>` で開いた場合は、Home を経由せず直接キャンバスで再生する
- 比較ウィンドウ(F7): Home で2つ以上選んで `c`(または比較ボタン)を押すと、選んだファイルを1つのウィンドウに入れて開く。表示は 並べる / スライダー / 差分 をウィンドウ上部の Segmented button かキャンバスの `c` で切り替える
  - 並べる: 全ファイルを並べ、1つ目を基準に同期再生する
  - スライダー: 1つ目と2つ目を重ね、境目(ドラッグできる縦線)より右に2つ目を出す
  - 差分: 1つ目と2つ目の差(画素ごとの差の絶対値)を出す。同じところは黒くなる
  - 3つ以上のときのスライダーと差分は、1つ目と2つ目を比べる
  - 再生コントロールは1ファイルのウィンドウと同じ(等倍 / フィットの切替だけは出さない)。操作は1つ目に効き、ほかは同期でついてくる。音を出すのは1つ目だけ
- 画像のウィンドウ(F8): フィット / 等倍(`z`)、`+` / `-` とマウスホイールで拡大・縮小(拡大は補間なし)、ドラッグで移動。下部のバーに、マウスの下の画素の座標と RGBA 値、倍率、縮小・拡大・フィット・等倍のボタンを出す。TIFF と 8bit を超える画像はサーバで 8bit の PNG にして表示し(`/api/image`)、値は元の 16bit の値を出す(`/api/pixels`)

### 4.3 見た目(Material Design 3)

- Material Theme Builder で作ったカラートークンを CSS 変数として持ち、ライト / ダーク自動切替
- コンポーネント: Navigation rail なし、Top app bar(小)、FAB、Assist chip(タブバー)、Slider(シークバー・音量)、Snackbar、Dialog(キー一覧・確認・文字列の送信)、Side sheet(操作パネル)、Segmented button(比較の表示)、Menu(再生速度)、Checkbox
- 角丸・エレベーション・モーションは MD3 のトークン値に合わせる
- 公式の Web コンポーネント @material/web は保守モードのため、トークンを使って自前実装する

### 4.4 重ねて出す画面

- **ヒント**: 今のモードで効く主なキー(hjkl の移動などの基本操作を含む)を、画面下に1行の帯で常時表示する。キャンバスでは、フォーカス中のウィンドウの種類(動画・比較・画像・ライブ・精度モード)と状態(録画中は R を「録画を止める」に、巻き戻し中は移動とライブへ戻るのキーを足す、入力モード中は抜けるキーだけ)で効くキーを先に出し、続けてキャンバス共通のキーをいつも出す。帯は閉じるボタンか操作パネルの設定で消せ、設定はブラウザごとに覚える。全キーの一覧は、`?` かヒントボタンで「キー一覧」ダイアログとして出す(Home・キャンバス・ウィンドウ操作モードの3つをまとめて)。キーマップのキーがキー一覧とヒントの帯に漏れなく載っていることは、単体テストで確かめる
- **操作パネル**: 上部のバーとヒントの帯を覆わないよう、その間に右端から出す。上から順に、(1) 設定(チェックボックス: ヒントの帯、Home では最新ファイルに追従と隠しファイルの表示、キャンバスでは同期再生中に全ウィンドウの音を出すか。ラジオ: タブバーの形)、(2) 画面上にボタンがない操作(Home: 選択をまとめて開く。キャンバス: 拡大・縮小・均等に並べる・全選択 / 解除・ほかを閉じる・全部閉じる・A-B ループ・全ウィンドウ再生 / 停止。拡大・縮小はタイル配置では行わず、自由配置でできる操作だと Snackbar で伝える)、(3) キーでできるすべての操作を Home・キャンバス・ウィンドウ操作に分けたボタン。マウスだけの人はここから全操作を行える。各ボタンには対応するキーを添える。チェックボックスはキー(`n`、`.`)で切り替えたときも同じ状態を示す
- **履歴ウィンドウ**: 直近に開いた10ファイルを新しい順に出す。Home・キャンバスのどちらからでも `r` か履歴ボタンで開き、キャンバスの縦横 90% の大きさで重ねて表示する。Home から親カラムを除いた2カラム(左にファイル名を閲覧範囲の起点からの相対パスで、右にプレビュー)。操作は Home と同じ(j/k で移動、Space で複数選択、Enter で開く、マウスのクリック・ダブルクリック)。`q` か閉じるボタンで閉じる。履歴はサーバ側(`~/.cache/dew/history.json`)に保存し、ブラウザを替えても同じものを出す

## 5. キーボード操作

方針は「再生のキーは対象のウィンドウに効く」。対象は、複数選択しているウィンドウがあればそれら全部、なければフォーカス中のウィンドウ。ウィンドウの切替・配置・選択は `w` で入るウィンドウ操作モードで行う。プログラムへの入力は専用の入力モードに入ったときだけ送る(vim のノーマル / インサートと同じ考え方)。

### 5.1 モード

1. Home モード: ファイル選択
2. キャンバス(ノーマル)モード: 再生操作とウィンドウ操作
3. ウィンドウ操作モード: `w` で入り、`q`(または Esc)で抜けるまで続く。モード中は1打鍵ずつ操作でき(右上のウィンドウへは `w l k`)、画面右下に候補を表示する(which-key 風)。モード中はバーとフォーカス枠の色で示す
4. 履歴ウィンドウ: Home と同じキーで履歴を選ぶ。`q` で閉じる
5. 入力モード: フォーカス中のライブウィンドウにキー・マウスを素通しする。枠の色が変わり、抜けるキーを常時表示

### 5.5 入力モード

- 入る: `i` かタイトルバーの入力モードのボタン。抜ける: `Ctrl+]`(アプリ側で使われにくいキー。設定での変更は未実装。9.2)か、同じボタン
- 入力モード中はすべてのキー(keydown / keyup)とマウス・ホイールをアプリへ送る。ゲームのような押しっぱなし入力にも対応
- ブラウザ予約キー(Ctrl+W、Ctrl+T など)は通常は奪えない。ウィンドウを全画面にすると Keyboard Lock API でこれらもアプリへ送れる
- 文字列をまとめて送りたい場合は `I` で送信用の入力欄を開く(日本語入力もここから)
- 入力モード中に変換中の文字(`isComposing`、`key` が `Process`)は送らない。日本語は `I` の入力欄から送る
- 抜けるとき、押したままのキーを離す(押しっぱなしにならないように)
- ドキュメントウィンドウ(15章)では、開いた直後から入力モードにし、`q` でも抜けられる(15.3)

### 5.6 実装上の注意

- キー判定は `KeyboardEvent.key` を基本にする。JIS 配列では `[` `]` `:` などの物理キー位置が US 配列と違うため、`code` だと刻印と動作がずれる
- 日本語 IME がオンのとき(`key` が `Process`)だけ、英字・数字キーを `code` で判定して操作を続けられるようにする。変換中(`isComposing`)は無視し、画面右上に「IME オン」を表示する
- ブラウザ予約キーと衝突しないよう、Ctrl 系はキーマップに使わない(入力モードを抜ける `Ctrl+]` だけは例外)
- 入力モードでアプリへ送るキーは、`key` から X11 の keysym に変換して送る。仮想ディスプレイ側のキー配列にない文字は空いているキーコードに一時的に割り当て、Shift が要る文字は Shift も押す。仮想ディスプレイ側のキー配列が US でも、押した文字どおりに届く
- キーマップは設定ファイル(TOML)で上書き可能(未実装。9.2)

## 6. アーキテクチャ

サーバは Rust の単一バイナリで、1ポートに HTTPS(UI・ファイル)と WebSocket(ライブ映像・音声・入力・通知)を載せる。ライブ描画の主経路は仮想ディスプレイのウィンドウ単位キャプチャで、プログラムには一切手を入れない。

```text
Ubuntu サーバ / WSL2(Docker コンテナ内も可)
├── 出力ディレクトリ(画像・動画)  ──ファイル変更──▶ ファイルAPI(inotify 監視・ffmpeg 変換)
├── GUI アプリ(無改変、dew run)  ◀─画面・音声 / 入力─▶ ウィンドウキャプチャ(ffmpeg x11grab・H.264 / Opus、XTest)
└── cv2.imshow フック(任意)      ──元フレーム──▶ 元フレーム受信(Unix ソケット)
                                                   │
                     dew サーバ(Rust 単一バイナリ、HTTPS + WebSocket 1ポート)
                                                   │
         リモート: HTTPS + トークン付き URL(直結) / WSL2: localhost / ssh -L は任意
                                                   │
                     Windows ブラウザ(TypeScript + React / MD3)
                     Home | キャンバス | WebCodecs で復号
```

### 6.1 ライブ描画の流れ(プログラム無改変)

1. `dew run python main.py` が、サーバに1つだけ作る共有のセッション(専用の Xvfb と PulseAudio。音の出ない null-sink に出させる)を用意し、`DISPLAY`、`PULSE_SERVER` を設定してコマンドを実行する。`dew env` で出した設定で起動したアプリも同じセッションに出る
2. サーバは X11 の新規ウィンドウを監視し(x11rb)、ウィンドウごとに ffmpeg の `x11grab` で、画面上のそのウィンドウの範囲を取り出す(上に重なったメニューなどの一時的な窓も一緒に映る。ADR 0012)。ほかのウィンドウが映り込まないよう、ウィンドウは仮想ディスプレイ上で重ならない位置に置き、大きさが変わったら置き直す(ADR 0009)
3. 同じ ffmpeg で H.264 にエンコード(NVENC が使えれば h264_nvenc、なければ libx264 の ultrafast・zerolatency。B フレームなし、キーフレームは1秒ごと。ADR 0014、0015)。各フレームに AUD を入れて区切る。途中からつないだブラウザには、最後のキーフレーム以降をまとめて送ってすぐ映す。音声は null-sink の monitor を ffmpeg で 10 ms 単位の Opus にする
4. WebSocket でブラウザへ送り、ブラウザは WebCodecs で復号してウィンドウごとの canvas に描画。音声は AudioDecoder で復号し、Web Audio で 50 ms 先に予約して鳴らす(アプリごとの音と、どのウィンドウにも結びつかないセッション音声。7.6、ADR 0013)
5. 入力モード中のキー・マウスは WebSocket で戻し、XTest でアプリへ注入
6. 未処理フレームが溜まったら古いものを捨て、遅延を積み上げない

精度モード(L3)では、自動注入したフックが cv2.imshow に渡された画像を可逆の PNG にして Unix ソケットで直接送り、キャプチャを経由せずに元フレームを表示する。X のウィンドウは作らず、入力モードのキーは waitKey に返す。キャンバスで閉じた窓は、アプリが描き続けても出し直さない(destroyWindow の後に描いたら新しい窓)。録画・巻き戻しの対象外(ADR 0017)。

### 6.2 HTTP / WebSocket API

通信の型は `crates/protocol` で定義し、ts-rs で `web/src/protocol/` に出力する。認証は Cookie(ブラウザ)か `Authorization: Bearer`(CLI)。

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/api/health` | 動いているかとインスタンス ID(CLI がサーバを再利用するとき) |
| GET | `/api/info` | 閲覧範囲の起点と Home の初期位置 |
| GET | `/api/tree?path=` | ディレクトリ一覧(種別・サイズ・更新時刻・読めるか) |
| GET | `/api/thumb?path=` | サムネイル(幅 320px の WebP、キャッシュ) |
| GET | `/api/sprite?path=` | シークバー用のサムネイル列 |
| GET | `/api/media?path=` | 原ファイル。Range 対応でシーク可能 |
| GET | `/api/media?path=&transcode=1&seg=N` | 変換した N 番目の 6 秒セグメント(fragmented MP4。7.4)。キャッシュの当否を `x-dew-cache` で返す |
| GET | `/api/probe?path=` | fps、コーデック、長さ、フレームのタイムスタンプ一覧、色深度、変換の要否 |
| GET | `/api/image?path=` | ブラウザで正確に表示できない画像(TIFF、16bit)を 8bit の PNG にしたもの |
| GET | `/api/pixels?path=` | 画像の元の画素値(16bit RGBA) |
| GET / POST | `/api/history` | 履歴(直近 10 ファイル)の取得 / 追加 |
| POST | `/api/open` | CLI からの表示指示(F10) |
| POST | `/api/live/session` | ライブ描画のセッションを用意し、つなぐ設定を返す(dew run / dew env) |
| POST | `/api/live/record` | ライブウィンドウの録画を始める・止める(L7。止めたときは保存したファイルを返す) |
| POST | `/api/shutdown` | サーバを止める(dew stop、停止ボタン) |
| WS | `/ws/events` | ファイル変更、表示指示、ライブウィンドウの一覧 |
| WS | `/ws/live/{window}` | ライブ映像の受信と、入力モードの入力・大きさの変更の送信(精度モードの窓は H.264 の代わりに PNG) |
| WS | `/ws/live-audio` | ライブ描画のセッション音声(どのウィンドウにも結びつかない音。Opus) |
| WS | `/ws/live-audio/{window}` | そのライブウィンドウのアプリの音(Opus。同じアプリのウィンドウは同じ音) |

フェーズ5〜7で足す API は 13.6(activate 中のシェルの登録)、14.3(`/open`)、16.8(CSV)、17.1(`/api/text`)にある。

### 6.3 技術選定

| 層 | 採用 | 用途 |
| --- | --- | --- |

| 映像の取り込みとエンコード | ffmpeg CLI(`x11grab` でウィンドウの範囲を取り込み、libx264 か NVENC で H.264。ADR 0009、0012) | H.264、NVENC |

| 見た目 | MD3 トークン(CSS 変数)+ 自前コンポーネント、Material Symbols の SVG(ADR 0007) | Material Design 3 |
| フック(L3) | 小さな Python パッケージ(サーバに同梱) | cv2.imshow の自動フック |

## 7. 詳細仕様

実装中に必ず判断が要る点をここで決めておく。

### 7.1 サーバの常駐と CLI

- `dew` はサーバが動いていなければバックグラウンドで起動し、URL を表示してすぐ端末に戻る。端末を閉じても(ssh が切れても)コンテナが動いている限りサーバは残る
- `dew --foreground` で前面実行(開発・デバッグ用)
- 接続中のタブもライブ描画もない状態が 12 時間続いたら自動停止。ただし `dew activate` 中のシェルがある間は止めない(13.6)

### 7.2 閲覧範囲と権限

- 閲覧できる範囲は既定で、最初に `dew` を起動したディレクトリを含む git リポジトリのルート(`.git` を親へたどって探す。git コマンドには頼らない)。git 管理外なら `$HOME`、起動したディレクトリが `$HOME` の外なら起動したディレクトリ(ADR 0021)。`--root <dir>` で変えられる(`--root /` でコンテナ全体)。トークンが漏れたときの被害を、作業中のプロジェクトに限るため
- Home の初期位置は、最初に `dew` を起動したディレクトリ
- 起動したときと `dew status` で、閲覧範囲と変え方(`dew stop` の後 `--root`)を出す
- 範囲外のパスを `dew <パス>` で開こうとしたら、`dew stop` してから `--root` を付けて起動し直すよう案内する
- 権限は dew を起動したユーザーのものに従う。読めないファイルは鍵アイコンで表示し、開こうとしたらエラーを出す
- シンボリックリンクはたどる。ただし `--root` 指定時は範囲外を指すリンクを開かない
- 削除・移動などのファイル操作は持たない(読み取り専用)

### 7.3 共有サーバでの負荷

- ffmpeg の同時実行数は既定 2(`--jobs`)。サムネイル生成は画面に見えているものから順に、低優先度(nice 10)で行う
- 1万件以上のディレクトリでも固まらないよう、一覧は仮想スクロールで描画し、サムネイルは表示範囲だけ作る
- ライブ描画のエンコードは既定で最大 2 スレッド。NVENC があればそちらに逃がす

### 7.4 変換とシーク

- 変換が必要なファイルは、6秒単位のセグメントに分けて要求された位置から変換する(HLS と同じ考え方)。ブラウザ側は Media Source Extensions で再生し、先の位置へシークしても待たずに再生できる
- 変換済みセグメントはキャッシュし、同じファイルの2回目は変換しない
- 変換中はシークバーに変換済み範囲を薄く表示する

### 7.5 フレーム精度

- 開いた時点で ffprobe からフレームごとのタイムスタンプ一覧を取得してキャッシュする(可変フレームレートの動画でも番号がずれないように)
- 表示中のフレームは `requestVideoFrameCallback` で取得し、その時刻からフレーム番号を求めて表示する
- コマ送りは「次のフレームのタイムスタンプへシーク」で実装する(1/fps を足すのではなく)

### 7.6 音声と自動再生

- ウィンドウが複数あるとき、音が出るのはフォーカス中のウィンドウだけ(既定)。`s` の同期再生中は全ウィンドウの音を出すかを設定で選べる
- 意図せず音が出て周りに迷惑をかけないよう、キャンバスには全体のミュートがある。Home からキャンバスへ入るたびに必ずオンにし、キャンバスに音声のある動画があれば、右上のミュートボタンに約5秒「ミュートを解除」と文字でも出す(その後はアイコンだけ)。`M` かボタンで切り替える
- 全体のミュートは各ウィンドウの音量・ミュートとは別に持つ。全体のミュートを切り替えても各ウィンドウの音量は変えず、解除すれば元の音量で鳴る
- キャンバスから Home へ戻るときは、キャンバスの動画をすべて一時停止する(ライブウィンドウは止めない)
- ブラウザは、ユーザーが一度もページ操作していないと音声付きの自動再生を止める。`dew <ファイル>` で外から再生を始めるときに備え、ページを開いたら最初に「クリックかキーで開始」の表示を出して一度だけ操作してもらう。以降はそのタブで自動再生できる
- ライブ描画の音声は、PulseAudio のストリームが持つプロセス ID と、X ウィンドウの `_NET_WM_PID` を突き合わせ、アプリのウィンドウに紐づける。紐づけできない音は「セッション音声」としてまとめて扱う。音のプロセスがウィンドウのプロセスの子孫でも紐づける。同じアプリのウィンドウは同じ音を共有する。ライブウィンドウの音も上の決まり(フォーカス中だけ鳴らすなど)に従い、セッション音声は全体のミュート以外では止めない(ADR 0013)

### 7.7 複数タブと再接続

- 同じサーバに複数のタブがつながっているときは、最後に操作したタブに `dew <ファイル>` の表示指示を送る
- WebSocket が切れたら自動で再接続し、キャンバスのウィンドウ配置と再生位置を復元する(配置はサーバ側で保持)

### 7.8 認証の細部

- Cookie はポートを区別しないため、同じホストの複数コンテナで Cookie 名が衝突しないよう、名前にインスタンス ID を含める(`dew_<id>`)。`HttpOnly`、`Secure`、`SameSite=Strict` を付ける
- URL のトークンは初回に Cookie へ移したら、アドレスバーからは消す(履歴に残さない)

### 7.9 ライブ描画の細部

- 仮想ディスプレイは 3840x2160 で起動し、ウィンドウマネージャは置かない。フォーカスは dew が `XSetInputFocus` で直接切り替える。アプリのウィンドウは、隠れた部分が欠けないよう dew が重ならない位置に置き直す
- アプリが起動時に作ってすぐ消すウィンドウ(pygame など)があっても監視を止めない
- メニューやツールチップなどの一時的な窓(override-redirect)は、親ウィンドウの映像に重ねて表示する。画面上の親の範囲を取り込むので、重なった部分はそのまま映る(ADR 0012)。はみ出してほかのアプリのウィンドウに重なったら、そのウィンドウを空いた場所へ移して映り込みを防ぐ。dew がウィンドウを動かしたときは、ウィンドウマネージャと同じく新しい位置をアプリへ知らせる(合成の ConfigureNotify)
- ブラウザ側でウィンドウの大きさを変えたときは、既定では表示を拡大縮小するだけでアプリには伝えない。`w r` でアプリのウィンドウサイズをブラウザ側の大きさに合わせる
- 等倍表示(`z`)は、Windows の表示倍率(125% など)を打ち消してディスプレイの1画素に合わせる
- アプリが終了したウィンドウは最後のフレームを残し、「終了」表示を付ける。`w x` で閉じる
- 動いているアプリのウィンドウをキャンバスで閉じたとき(閉じるボタン、`w x` など)は、デスクトップの × と同じく WM_DELETE_WINDOW でアプリに閉じるよう頼み、キャンバスからは消す。どうするか(図を閉じる、終わる、無視する)はアプリが決め、dew は無理に止めない。頼みに対応していないアプリや無視したアプリは動き続ける(止めるのは端末か `dew stop`)
- OpenGL アプリは Mesa のソフトウェア描画で動く。重い場合に備え、`dew doctor` で GPU 付き仮想ディスプレイの可否を表示する

### 7.10 配布と依存の導入

- dew は単一バイナリで、L3 の Python フックもバイナリに同梱し、初回実行時に `~/.cache/dew/python/` へ展開する(pip install 不要)
- 実行時の依存(ffmpeg、Xvfb、pulseaudio)がコンテナにない場合、`dew doctor` が機能ごとに要るツールと apt のインストールコマンドを表示する。ツールが足りなくても、そのツールを使わない機能は動く(ADR 0019): ファイルの閲覧とブラウザで再生できる形式の再生はツール不要、動画の情報・コマ送りは ffprobe、サムネイル・変換・TIFF は ffmpeg、ライブ描画は Xvfb と ffmpeg(なければ dew run が入れ方を出して止まる)、ライブ描画の音は pulseaudio(なければ音なしで映す)、録画は ffmpeg(なければ始めるときに入れ方を出す)
- 配布経路:
  - 自分の環境: 非公開リポジトリの GitHub Releases に置き、`gh release download` で取得
  - 知り合いへの配布(少人数): バイナリ1ファイルを直接渡す。受け取った人は `~/.local/bin` などに置いて `chmod +x` する
  - 公開: ソースのリポジトリ `kWat0M/dew` を公開し、その GitHub Releases に配布物を置く(ADR 0020。以前はバイナリだけの `kWat0M/dew-releases` に置いていた)
- 配布用ビルドは、OS のライブラリに依存しない静的リンク(`x86_64-unknown-linux-musl`)を目標にする。依存の都合で静的リンクできない部分は、純 Rust 実装のクレートを優先して避ける。どうしても残る場合は古い glibc(Ubuntu 20.04 相当)でビルドして互換範囲を広げ、その判断を ADR に残す
- `dew update` で自己更新できるようにする。更新元(非公開 Releases / 公開リポジトリ)は設定で切り替える(既定はソースと配布物を置く公開リポジトリ `kWat0M/dew`、環境変数 `DEW_UPDATE_REPO` で変えられる。非公開ならログイン済みの `gh` で取る)。どちらにも届かない環境では何もせず、手動更新の方法を表示する(ADR 0018)
- `dew --version` でバージョンとビルド日時を表示する
- リポジトリに LICENSE を置き、利用条件を明記する(知り合いへの配布を許可し、再配布は不可、など。文面は人が決める)

### 7.11 エラーの見せ方

- 再生できない・変換に失敗したときは、ウィンドウ内に理由(ffmpeg のエラー要約)と「ログを見る」を表示する
- サーバ側の警告(依存不足、キャッシュ上限、ポート未公開の疑い)は MD3 の Snackbar で出す

## 8. 設計判断(経緯)

### 8.1 ssh -L をサーバ側から自動で張れるか → できない

ポート転送は ssh クライアント(Windows 側)が要求するもので、サーバ上のプログラムからクライアントに転送を追加させる仕組みはない。OpenSSH のエスケープ `~C` はクライアントのキー入力が必要で、近年の版では既定で無効。WezTerm 側で自動化するには wezterm.lua の設定が要る。そこで既定を直結モード(HTTPS + トークン付き URL)にし、Windows 側の設定を不要にした。前提はサーバの待ち受けポートに Windows から届くこと。

### 8.2 F10 の動作

`dew out/result.mp4` を実行すると、起動中のサーバに通知が届き、接続中のブラウザタブがキャンバスにそのファイルのウィンドウを追加して再生を始める。新しいタブは開かない。サーバから Windows のブラウザを新規に開く手段は一般にはないが、WezTerm を使う人は、端末のユーザー変数を介して開かせられる(14.3)。

- yazi 連携: yazi の opener に `dew "$@"` を登録すれば、yazi で Enter を押すだけで、開いておいたブラウザタブに映像が出る
- ブラウザタブが1つもないとき: 表示指示を2分間予約し、WezTerm に開かせる。端末の通知と、標準エラー出力への URL の表示もする(14.4、14.5)

### 8.3 ライブ描画を Selkies 埋め込みにしない理由

| 観点 | Selkies 埋め込み | 自前実装 |
| --- | --- | --- |
| ウィンドウ単位の表示(L2) | 不可。デスクトップ全体が1枚の映像 | 可 |
| キーボードだけの窓操作 | 不可。キー入力はリモートへ送られ、キーマップと衝突 | 可。入力モードで分離 |
| 見た目(MD3)の統一 | 不可。独自 UI を iframe で埋め込む形 | 可 |
| 配置 | 別プロセス・別ポート、Python + 依存一式 | 単一バイナリ |
| 精度モード(L3)、録画・巻き戻し(L7) | なし | あり |

Selkies は自前実装の遅延・画質を比べる基準として使う。自前実装が間に合わない間は「デスクトップモード」として Selkies を起動する選択肢を残す。

仮想ディスプレイ(Xvfb)には GPU がないため、OpenGL を使うアプリはソフトウェア描画になり重い。GPU のあるサーバでは GPU 付きの仮想 X(NVIDIA の Xorg + dummy 設定や VirtualGL)を選べるようにする。

### 8.4 フロントエンドを TypeScript + React にした理由

Rust だけ(Leptos 等)でも書けるが、(1) 動画のデコードと描画はブラウザ内部のハードウェア処理でフロントの言語は性能にほぼ効かない、(2) WebCodecs・Keyboard Lock・Web Audio は TypeScript から素直に使えるが Rust の web-sys では一部が不安定版扱い、(3) MD3 はどちらでも自前実装で、React の方が部品・事例が多い。速さが効くサーバ側は Rust で書く。型は ts-rs で Rust から生成して通信の型ずれを防ぐ。

## 9. 開発フェーズと決定事項

各フェーズ単体で使える状態にして進める。最も重いのはフェーズ3のウィンドウ単位キャプチャ。

1. **フェーズ1(ファイルビューア)**: CLI、Home、キャンバス(ファイル再生ウィンドウ)、F1–F6, F10、直結モード + HTTPS + トークン、複数コンテナ運用
2. **フェーズ2(比較・画像)**: F7, F8、同期再生
3. **フェーズ3(ライブ描画)**: `dew run` / `env`、Xvfb + 音声、ウィンドウ単位キャプチャ(L1, L2, L4, L5)、入力モード(L6)
4. **フェーズ4(精度・記録)**: L3(cv2.imshow 自動フック)、L7(録画・巻き戻し)、NVENC
5. **フェーズ5(シェル連携・外部ツール連携)**: `dew activate` / `deactivate`(13章)、タブがないときに `dew <ファイル>` から表示までたどり着く仕組み(14章)
6. **フェーズ6(ドキュメントウィンドウ・Markdown)**: F13 の土台と F12(15章、17章)
7. **フェーズ7(CSV)**: F11(16章)

フェーズ5〜7の機能は、フェーズ4のあとに追加の仕様としてまとめたもの(2026-10-21)。小さく独立したシェル連携・外部ツール連携を先に作り、続いてドキュメントウィンドウの土台を比較的軽い Markdown と一緒に作り、最も大きい CSV を最後にする。

## 10. 開発環境(Claude Code)

開発は WSL2 上の Docker コンテナで行い、git 操作もコーディングも Claude Code もすべてその中で動かす。コンテナは手元のテンプレート(dotfiles の開発コンテナ見本)から作った `Dockerfile` / `compose.yaml` / `dev.sh` / `.env.example` で定義する。セクション番号 [1]〜[6] はテンプレートと共通で、[6] が dew 固有。

使い方: `.env.example` を `.env` にコピーして値を埋め、`./dev.sh` で起動して入る(`./dev.sh build` で作り直し、`./dev.sh down` で停止)。

### 10.1 開発用コンテナに入れるもの(Debian trixie ベース)

| 分類 | パッケージ / ツール | 用途 |
| --- | --- | --- |
| [1]〜[5] テンプレート | starship、chafa、yazi、ffmpeg、git、lazygit、gh、mpv、Neovim、Claude Code(公式インストーラ、版を固定) | 共通の作業環境 |
| ビルド基盤 | build-essential、pkg-config、clang、nasm、cmake、musl-tools、libopus-dev | Rust のネイティブ依存、musl 静的ビルド |
| Rust | rustup(stable)、rustfmt、clippy、rust-src、`x86_64-unknown-linux-musl` ターゲット、cargo-nextest | サーバ本体とテスト、配布用ビルド |
| フロント | Node.js 24 LTS(NodeSource)、pnpm(corepack。版は package.json の `packageManager` で固定) | Web UI のビルド |
| メディア | ffmpeg | 変換、テスト素材の生成 |
| 仮想ディスプレイ | xvfb、x11-utils、xdotool | ライブ描画の開発と自動テスト |
| 音声 | pulseaudio、pulseaudio-utils | 音声キャプチャの開発 |
| OpenGL | libgl1-mesa-dri、mesa-utils | OpenGL アプリの表示確認 |
| テスト用アプリ | python3、python3-opencv(GUI 付き)、python3-matplotlib、python3-tk、python3-pygame(すべて apt) | プログラム無改変の確認 |
| シェル連携 | zsh(bash は元から入っている) | `dew activate` を bash と zsh の両方で確かめる(13章) |
| E2E | google-chrome-stable、fonts-noto-cjk(Playwright はプロジェクトの devDependencies で入れる)、Playwright の Firefox(`playwright install firefox`) | ブラウザでの自動確認 |
| エディタ | rust-analyzer、vtsls(mason)、Rust / TypeScript / TSX ほかの treesitter パーサー | 補完・定義ジャンプ |

E2E には Playwright 同梱の Chromium ではなく Google Chrome を使う(`channel: 'chrome'`)。同梱の Chromium は H.264 / AAC を再生できない。Firefox 系への対応を確かめるため、Playwright の Firefox も使う(`playwright install firefox` でダウンロードする)。

### 10.2 compose.yaml の主な設定

- サービス名・ホスト名: `dew`
- ポート: 8765(dew 本体)と 5173(Vite の開発サーバ)を公開。番号は `.env` の `DEW_PORT` / `VITE_PORT` で変えられる。Windows のブラウザから `https://localhost:8765` / `http://localhost:5173` で開ける。Vite は `server.host` を `0.0.0.0` にする
- 環境変数: `DEW_PUBLIC_HOST=localhost`、`DEW_PUBLIC_PORT=${DEW_PORT}`
- リポジトリは `/home/dev/${PROJECT_PATH}` にマウントする(ホームからの相対パスをホストとそろえる。Claude Code の会話履歴の同期のため)。`target/` と `node_modules/` はリポジトリ内に置く
- 名前付きボリューム: `cargo-home`(~/.cargo)、`pnpm-store`(~/.local/share/pnpm)、`gh-config`(~/.config/gh)。持ち主の UID は `dev.sh` が合わせる
- git: ホストの ssh-agent を転送する(秘密鍵はコンテナに入れない)。git / ssh の設定は dotfiles からコピー
- Claude Code: ホストの `~/.claude` をマウントして、ログイン情報・会話履歴を共有する
- WSLg: X11 / Wayland / PulseAudio のソケットを共有する(テスト用アプリを Windows 側に直接出して見比べる用)。`dew run` は自前の Xvfb と pulseaudio を起動し、子プロセスの `DISPLAY` / `PULSE_SERVER` を上書きする
- 共有メモリ: `ipc: host`(ホストの /dev/shm を使う。Chrome と Xvfb もこれで足りるため `shm_size` は指定しない)

リモートサーバでの確認(直結モード、複数コンテナ)は各フェーズの終わりにまとめて行う。ビルドしたバイナリをサーバのコンテナに持ち込んで試す。

### 10.4 人手なしで動作確認する方法

- テスト素材は ffmpeg で生成する(`testsrc2` の映像にフレーム番号を焼き込み、`sine` の音を付ける)。コマ送りやシークの正しさを、画面に映った番号で判定できる
- サーバの単体・結合テストは `cargo nextest run`
- UI は Playwright + Chrome のヘッドレスで、再生位置の進行、キー操作、スクリーンショットを確認
- ライブ描画は、テスト用アプリ(フレーム番号を描画し、決まった周波数の音を鳴らす)を `dew run` で起動し、受信した映像・音声から遅延と fps を測る

### 10.5 Claude Code の権限設定(.claude/settings.json の方針)

- 許可: `cargo`、`pnpm`、`npx playwright`、`ffmpeg`、`ffprobe`、`Xvfb`、`python3`、`git`(commit まで)

- Claude Code は `docs/spec.md` を正とする

## 13. シェル連携: `dew activate` / `dew deactivate`

### 13.1 シェル関数が必要な理由

実行したコマンドは、自分を呼んだシェルの環境変数を変えられない。`eval "$(dew env)"` が `eval` を必要とするのはこのため。`dew activate` もそのままでは同じ制約を受ける。そこで、conda や pyenv と同じように、シェルに小さな関数 `dew` を定義する。`activate` / `deactivate` のときだけ、この関数が dew の出力を `eval` する。

### 13.2 導入

| コマンド | 動作 |
| --- | --- |
| `dew shell-init <bash\|zsh>` | シェル関数のコードを標準出力に出す。rc ファイルに `eval "$(dew shell-init bash)"` と書いて使う |
| `dew setup-shell` | `$SHELL` からシェルを判定し、`~/.bashrc` または `~/.zshrc` に上の1行を追記する。追記前に y/N で確認し、すでにあれば何もしない |

シェル関数の中身(bash / zsh 共通):

```sh
dew() {
  case "${1:-}" in
    activate|deactivate)
      local __dew_out
      __dew_out="$(command dew "$@" --emit-shell --shell-pid $$)" || return $?
      eval "$__dew_out" ;;
    *)
      command dew "$@" ;;
  esac
}
```

- `$(...)` の中はサブシェルなので、dew 側で親プロセスID(getppid)を取ると、すぐ終わるサブシェルのIDになる。シェル本体のPIDは `--shell-pid $$` で明示的に渡す(bash / zsh ともに `$$` はサブシェル内でも元のシェルのPID)
- シェル連携なしで `dew activate` を直接実行した場合(`--emit-shell` がない場合)は、導入方法(`dew setup-shell`)を表示して終了コード 1 で終わる
- 開発用コンテナの rc ファイルへの追記は人が行う。Dockerfile では追記しない(ADR 0022)
- fish などほかのシェルは対象外

### 13.3 `dew activate` の動作

1. サーバとライブ描画用の仮想ディスプレイ・音声サーバが動いていなければ起動する
2. 変更する環境変数の現在の値を `_DEW_SAVED_<名前>` に保存する。未設定だったものは `__DEW_UNSET__` という印を保存する
3. 環境変数を設定する

| 変数 | activate 中の値 | 理由 |
| --- | --- | --- |
| `DISPLAY` | dew の Xvfb(`dew env` と同じ値) | X11 アプリの表示先 |
| `PULSE_SERVER` | dew の音声サーバ(`dew env` と同じ値) | 音声の出力先 |
| `WAYLAND_DISPLAY` | 未設定にする | 開発用コンテナでは WSLg の値が入っている。Wayland 対応のアプリが dew を通らず Windows 側に出るのを防ぐ |
| `QT_QPA_PLATFORM` | `xcb` | Qt を X11 に固定する |
| `GDK_BACKEND` | `x11` | GTK を X11 に固定する |
| `SDL_VIDEODRIVER` | `x11` | pygame(SDL)を X11 に固定する |
| `DEW_ACTIVE` | `1` | 状態の目印(プロンプト表示、二重 activate の判定) |
| `PYTHONPATH` | `--exact` 指定時のみ、L3 のフックを先頭に追加 | 精度モード |

4. シェルのPIDをサーバに登録する(13.6)
5. 1行だけ表示する: `dew: 有効にしました(ディスプレイ :100)。dew deactivate で戻します`

- 実際に設定する変数は、現在の `dew env` / `dew run` の実装に合わせる。上の表は最低限の要件
- すでに activate 中なら何もせず、その旨を表示する(保存した元の値は上書きしない)

### 13.4 `dew deactivate` の動作

1. `_DEW_SAVED_<名前>` から元の値に戻す。`__DEW_UNSET__` のものは unset する
2. `_DEW_SAVED_*` と `DEW_ACTIVE` を unset する
3. サーバの登録を消す。サーバが止まっていてもエラーにせず、環境変数だけは必ず戻す
4. activate 中でなければ、その旨を表示して何もしない

### 13.5 プロンプト表示

- starship を使っている場合(`STARSHIP_SHELL` が設定されている)は、PS1 を書き換えない。starship は毎回 PS1 を作り直すため、書き換えても上書きされる。代わりに、`dew shell-init` のヘルプに次の設定例を載せる

```toml
[env_var.DEW_ACTIVE]
format = "[dew]($style) "
style = "bold blue"
```

- starship がない場合は、bash の PS1 と zsh の PROMPT の先頭に `(dew) ` を付け、deactivate で戻す
- `DEW_NO_PROMPT=1` のときはプロンプトに触れない

### 13.6 サーバとの連携

- サーバは activate 中のシェルを、PID と開始時刻(`/proc/<pid>/stat` の starttime)で登録する。開始時刻も見るのは、PID の再利用で別プロセスを取り違えないため
- 登録は1分ごとに点検し、終了したシェルは消す(端末を閉じた場合も自動で消える)
- activate 中のシェルが1つでもある間は、無操作の自動停止(7.1)をしない
- `dew stop` は、activate 中のシェルがあれば数を表示して確認する(`--force` で確認なし)
- 仮想ディスプレイ番号は `~/.local/share/dew/state.json` に保存し(server.json は停止で消えるため。ADR 0023)、サーバを再起動したときも同じ番号が空いていれば再利用する。activate 中のシェルの `DISPLAY` が無効にならないようにするため
- 待ち受けポートも同じく、前回の番号を `~/.local/share/dew/` に保存し、`--port` / `DEW_PORT` の指定がなければ、次の起動でまず前回の番号を試す。空いていなければ 8765 から順に探す。`--network host` で起動し直したときに、開いていたタブのアドレスが変わらないようにするため(ADR 0022)
- `dew status` に activate 中のシェル数を表示する

### 13.7 既存コマンドとの関係

- `dew env` はそのまま残す(後方互換)
- `dew run <コマンド>` もそのまま。activate 中に `dew run` を使っても同じ仮想ディスプレイに出る

## 14. 外部ツール連携(ブラウザのタブがないとき)

### 14.1 方針

yazi などから `dew <ファイル>` を実行したとき、接続中のブラウザタブがないと何も見えない。これを次の3段構えで解消する。

1. **タブを開いたままにしやすくする**: サーバの再起動やトークン変更でタブが無効にならないようにし、固定タブとして置いておけば常に届くようにする(14.2)
2. **端末からブラウザを開く**: タブがないときは、端末にエスケープシーケンスを送り、WezTerm に Windows の既定ブラウザで URL を開かせる。ssh や docker exec を挟んでも届く(14.3)
3. **それ以外の端末のための代わり**: 通知の表示と、開く予定のファイルの予約(14.4)

### 14.2 タブを開いたままにしやすくする

- **トークンの保存**: トークンをインスタンスごとに `~/.local/share/dew/token`(権限 600)に保存し、サーバを再起動しても同じものを使う。`dew rotate-token` で作り直す
- **自動再接続**: タブはサーバが止まっている間も、5秒ごとに再接続を試みる。その間は「サーバ停止中」と表示する。ページを読み直さずにつなぎ直すので、キャンバスのウィンドウはそのまま残る(サーバ側で配置を持って復元するのは 9.2 のとおり未実装)
- **裏にあるタブへの知らせ**: タブが裏にあるときに表示指示が届いたら、次の2つを行う
  - タブのタイトルの先頭に `●` を付ける(タブを表に出したら消す)
  - 設定で通知を許可していれば、ブラウザの通知(Notification API)を出す。クリックするとタブを表に出す。自己署名証明書などで通知が使えない環境では、設定項目を無効にする

### 14.3 端末からブラウザを開く(WezTerm)

**dew 側の動作**

- 接続中のタブがないとき、`dew <ファイル>` は制御端末(`/dev/tty`)に次の2つを書き込む
  - `ESC ] 1337 ; SetUserVar=dew_open=<URL の base64> BEL`(WezTerm のユーザー変数)
  - `ESC ] 777 ; notify ; dew ; ブラウザで開きます BEL`(端末の通知)
- 書き込み先は標準出力ではなく `/dev/tty` にする。yazi などから呼ばれ、標準出力が捨てられていても端末に届くようにするため。制御端末がなければ書き込まない
- `$TMUX` があるときは、tmux の passthrough(`ESC P tmux; ... ESC \`)で包む。tmux 側には `allow-passthrough on` が必要。この点を `dew doctor` で案内する
- URL は `https://<公開ホスト>:<公開ポート>/open?path=<パス>&token=<トークン>`。開いたページは、既存のトークン処理(Cookie へ移してアドレスバーから消す)のあとで、そのファイルを開く

**WezTerm 側の設定(1回だけ、使う人だけ)**

この設定を足すかは、ユーザーごとに選ぶ。足さない人は 14.4 の方法で使える。`dew setup-wezterm` が、次の設定を表示する(ファイルへの書き込みはしない)。

```lua
-- dew: 端末からブラウザを開く
wezterm.on('user-var-changed', function(window, pane, name, value)
  if name == 'dew_open' and value:match('^https?://[^/]+/open%?') then
    wezterm.open_with(value)
  end
end)
```

- 開く URL は `http(s)://.../open?` の形のものに限る。端末に表示した細工ファイルなどから、任意の URL を開かれないようにするため
- すでに `user-var-changed` のハンドラがある設定では、その中に条件分岐を足してもらう(ハンドラは1つしか持てない)。この点を表示する文面にも書く
- 人が確かめるときは、ふだんの `wezterm.lua` を変えずに、ふだんの設定を読み込んでハンドラを足すだけのテスト用の設定を作り、`wezterm --config-file <テスト用の設定> start` で別のウィンドウを開いて試す(閉じれば何も残らない)。自動テストでは、疑似端末に書き込まれるシーケンスまでを確かめる

### 14.4 WezTerm 以外のための代わり

- **予約**: タブがないときの表示指示は、サーバが2分間だけ保持する。その間にタブがつながったら、そのファイルを開く(手で URL を開いた場合も含む)。予約は最新の1件だけで、新しい指示が来たら置き換える
- **通知**: 14.3 の OSC 777 の通知は、WezTerm 以外でも対応端末では表示される
- **標準エラー出力**: 「ブラウザのタブがありません」と URL を1行表示する
- **クリップボード**(既定はオフ): 設定 `open_fallback_clipboard = true` のときは、OSC 52 で URL を端末のクリップボードにコピーする。クリップボードを勝手に上書きしないよう、既定はオフにする

### 14.5 `dew <ファイル>` の判定の流れ

1. 接続中のタブがある → 最後に操作したタブに表示指示を送る(既存の F10)。そのタブが裏にあれば 14.2 の知らせを出す
2. タブがない → 予約する(14.4)。続けて `/dev/tty` に WezTerm のユーザー変数と通知を書き、標準エラー出力に URL を表示する
3. どちらの場合も、すぐに終了する(終了コード 0)

### 14.6 追加・変更する CLI

| コマンド | 動作 |
| --- | --- |
| `dew url --open` | 14.3 の方法で、端末からブラウザに Home を開かせる |
| `dew url --copy` | OSC 52 で URL をクリップボードにコピーする |
| `dew setup-wezterm` | 14.3 の WezTerm 設定を表示する |
| `dew rotate-token` | トークンを作り直す。接続中のタブは切断される |

### 14.7 yazi の設定例

`dew doctor` のヘルプと README に載せる。`orphan = true` は付けない。dew はすぐ終わるので不要で、付けると制御端末がなくなり 14.3 が働かない。

```toml
[opener]
dew = [
  { run = 'dew "$@"', desc = "dew で開く", for = "unix" },
]

[open]
prepend_rules = [
  { mime = "video/*", use = ["dew", "play"] },
  { mime = "image/*", use = ["dew"] },
  { url = "*.csv", use = ["dew", "edit"] },
  { url = "*.tsv", use = ["dew", "edit"] },
  { url = "*.md", use = ["edit", "dew"] },
]
```

ルールのキー名(`url` / `name`)は yazi の版によって異なるため、開発用コンテナに入っている yazi の版の書き方に合わせる。Markdown は編集することが多いので、Enter はエディタを先にしている。

## 15. ドキュメントウィンドウ(CSV / Markdown 共通)

### 15.1 位置づけ

- キャンバスのウィンドウ種別に「ドキュメント」を追加する。既存のファイル再生ウィンドウ・ライブウィンドウと同じく、フローティングウィンドウとして扱う(`w` コマンド、Tab、番号での選択、最大化などはそのまま使える)
- 読み取り専用。編集機能は持たない
- 対象の拡張子: CSV は `.csv` `.tsv`、Markdown は `.md` `.markdown`

### 15.2 開き方

- Home で Enter、`dew <ファイル>`(F10)、Markdown 内のリンク(17.4)
- 同じファイルがすでにキャンバスにあれば、新しく開かずにそのウィンドウにフォーカスする

### 15.3 キー操作と入力モード

- ドキュメント固有の操作(スクロール、セル移動、リンクヒントなど)は入力モードで行う
- ドキュメントウィンドウを開いた直後は、そのウィンドウにフォーカスして入力モードに入る。yazi から開いてすぐ `j` で読めるようにするため(設定 `document_auto_input = false` で無効にできる)
- 入力モードを抜けるキー:
  - `Ctrl+]`: すべてのウィンドウ共通(既存)
  - `Esc` では抜けない(ライブウィンドウの抜け方に合わせる。2026-10-22 変更)。検索欄で文字を打っている間だけ、`Esc` で検索欄を閉じる。リンクヒントは `Backspace`、目次は `o` か `Backspace` で閉じる
  - `q`: ドキュメントウィンドウだけ。開いているもの(ヒント、目次など)があっても、すぐに入力モードを抜ける。`Ctrl+]` も同じで、検索欄で文字を打っている間も効く(ライブウィンドウではアプリが使うので対象外。2026-10-21 追加)
- 入力モードは、キャンバスが表に出ている間だけ効く。リンクなどで Home や履歴に移ったときは、そちらのキー操作がすぐ効く(キャンバスに戻ると入力モードに戻る)
- ノーマルモードでドキュメントウィンドウにフォーカスしているとき、再生用のキー(`j` `k` `l` `Space` `,` `.` `0`–`9` など)は効かない。押したら Snackbar で「i で操作できます」と1回だけ表示する
- キーの判定は既存の方針どおり `KeyboardEvent.key` を基本とし、IME 有効時は `code` で判定する。Ctrl 系のキーは使わない(`Ctrl+]` を除く)

### 15.4 ファイルの更新

- ファイルの変更を監視し(既存の F4)、変更されたら1秒以内に再読み込みする
- 再読み込み後も、スクロール位置・選択中のセル・表示設定を保つ。CSV で行数が減って位置が範囲外になる場合は、末尾に寄せる
- ファイルが削除されたら、最後の内容を残して「削除されました」と表示する

### 15.5 Home のプレビュー

- CSV: 先頭20行・最大10列を小さな表で表示する。文字コードと区切り文字も表示する
- Markdown: 先頭から最大 200 行を描画して表示する(リンクヒントなどの操作はなし)

### 15.6 遅延ロード

- CSV と Markdown の描画コードは、それぞれ別のチャンクに分け、最初に開いたときに読み込む(`React.lazy` + 動的 import)
- KaTeX の CSS とフォント、コードの色分けの CSS も Markdown のチャンクに含める
- 初期バンドルには、`react-markdown`、`katex`、`@tanstack/react-table`、`@tanstack/react-virtual` を含めない(受け入れ基準で確認する)

### 15.7 UI 部品

- ポップオーバー、メニュー、ダイアログには Radix UI のプリミティブを使う
- shadcn/ui は Tailwind CSS のクラスで見た目を付けているが、dew の UI は MD3 のトークンだけで色・角丸・影を指定する方針。そのため Tailwind は導入せず、shadcn/ui のコードを取り込む場合はクラスを既存の MD3 トークンに置き換える
- フロントエンドに追加するパッケージは、`web/package.json` の依存として版を固定する

### 15.8 文字コード

CSV と Markdown で同じ判定をサーバ側で行い、UTF-8 に変換してから使う。

1. BOM があれば、それに従う(UTF-8 / UTF-16)
2. UTF-8 として正しければ UTF-8
3. それ以外は判定ライブラリで推定する(主に Shift_JIS(CP932)と EUC-JP)
4. 判定結果はウィンドウ下部に表示し、設定から手で切り替えられる(UTF-8 / Shift_JIS / EUC-JP)

ライブラリは `encoding_rs`(変換)と `chardetng`(推定)。Excel が出力する日本語の CSV は Shift_JIS が多いため、この判定が必要になる。

## 16. CSV

### 16.1 小規模モードと大規模モード

| | 小規模モード | 大規模モード |
| --- | --- | --- |
| 条件 | ファイルサイズ 20 MB 未満、かつ 20万行未満 | それ以外 |
| 解析 | サーバ(Rust、`csv-core`)が全件解析し、列単位の JSON でブラウザに送る | サーバが DuckDB に読み込む |
| ソート・フィルター・検索 | ブラウザ(TanStack Table) | サーバ(DuckDB)。ブラウザは表示範囲のページだけ受け取る |

- 判定は、まずファイルサイズで行う。20 MB 未満なら全件解析し、行数が20万行以上だった場合は大規模モードに切り替える
- 閾値は設定で変えられる(`csv_small_max_bytes`、`csv_small_max_rows`)
- ウィンドウ下部に、どちらのモードかを表示する

### 16.2 読み込み

- **解析**: `csv-core`(または同じ作者の上位クレート `csv`)を使う。引用符内の改行・区切り文字・`""` のエスケープに対応する
- **区切り文字**: `.tsv` はタブ。`.csv` は先頭 64 KB から `,` `;` `\t` `|` を推定する。設定から手で変えられる
- **ヘッダー**: 1行目をヘッダーとして扱う。1行目のすべての値が数値なら、ヘッダーなしと判断して列名を「列1, 列2, …」にする。設定から切り替えられる
- **列数が不揃いな行**: 足りない列は空として、多い列は「列N」として列を追加して表示する。ウィンドウ下部に「列数が不揃いな行: N 行」と警告を出す
- **型の推定**: 先頭 1,000 行(小規模モードは全行)から、列ごとに次の順で決める。推定はサーバの1か所(Rust)で行い、大規模モードでは DuckDB に列の型を明示して渡す。そうすることで、両モードで型と並び順を一致させる

| 型 | 条件 |
| --- | --- |
| 整数 | すべて整数(空は除く) |
| 小数 | すべて数値(指数表記を含む) |
| 真偽値 | すべて `true` / `false`(大文字小文字を区別しない) |
| 日付・日時 | すべて ISO 8601(`2026-10-21`、`2026-10-21T12:00:00` など) |
| 文字列 | それ以外。`1,234` のような桁区切り付きの数値も文字列として扱う |

- 空のセルは null として扱う

### 16.3 表示

- 表は自作の React コンポーネントで作る。状態管理(列・ソート・フィルター・列幅)は TanStack Table、仮想スクロールは TanStack Virtual を使う
- **仮想スクロール**: 行も列も、画面内の分だけを描画する。列の仮想化は、列数が 50 を超えたら有効にする
- **常に見える部分**: ヘッダー行と行番号の列は、スクロールしても表示したままにする。行番号は元ファイルの行番号(ソートしても変わらない)
- **数値**: 右寄せにする。null は薄い「—」で表示する
- **長い文字列**: 1行に収め、はみ出す分は「…」で省略する。Enter でセルの全文を表示する(セルインスペクタ)
- **選択中のセル**: MD3 の primary 色の枠で示す。選択中のセルが画面外に出たら、自動でスクロールして見えるようにする
- **ウィンドウ下部の表示**: 行数(フィルター後 / 全体)・列数・選択中のセル(例: `C7`)・ソートの状態・文字コード・区切り文字・モード

**表示だけを変える機能**(元のデータは変えない。`y` でコピーするのは元の値)

| 機能 | 内容 |
| --- | --- |
| 丸め | 数値の列ごとに、小数の桁数を「そのまま / 0〜10桁」から選ぶ。表示には `Intl.NumberFormat` を使い、桁区切りの有無も列ごとに選べる |
| 行の強調 | (1) マーク: 選択中の行を手で強調する。(2) 条件付き強調: 「列・条件・値」のルールで、一致する行に色を付ける。色は MD3 の container 系の色(primary / secondary / tertiary / error)から選ぶ。ルールは4つまで |
| 表示名の変更 | 列の見出しに別名を付ける。元の列名はツールチップで見られる |
| 列を隠す | 列ごとに非表示にする。すべて再表示する操作もある |
| 列の固定 | 列を左に固定し、横スクロールしても見えるようにする |
| 列幅 | キーで広げる・狭める、内容に合わせる |

### 16.4 ソート・フィルター・検索

- **ソート**: 複数列に対応する(第1キー、第2キー…)。数値・日付は値の大小、文字列は Unicode 順(大文字小文字を区別しない)で並べる。null は常に末尾
- **列のフィルター**: 列ごとに条件を設定する。複数の列の条件は AND で組み合わせる

| 列の型 | 条件 |
| --- | --- |
| 文字列 | 含む / 一致 / 前方一致 / 空 / 空でない(大文字小文字を区別しない) |
| 数値・日付 | = / ≠ / < / ≤ / > / ≥ / 範囲 / 空 / 空でない |
| 真偽値 | true / false / 空 |

- **検索**: すべての列から部分一致(大文字小文字を区別しない)で探す。一致したセルを強調し、`n` / `N` で順に移動する。行の絞り込みはしない(絞り込みはフィルターで行う)
- 正規表現は使わない。ブラウザ(JavaScript)と DuckDB で正規表現の書き方が違い、両モードで結果がずれるため
- 大規模モードと小規模モードで、同じ条件の結果(並び順を含む)が一致すること

### 16.5 大規模モード(DuckDB)

- **読み込み**: 初回に開いたとき、UTF-8 以外なら UTF-8 に変換してから、DuckDB のデータベースファイルに読み込む。元の行番号の列 `__row` を付ける。保存先はキャッシュ(`~/.cache/dew/csv/`)で、ファイルのパス・サイズ・更新時刻をキーにする。キャッシュの上限(既存の 5 GB)に含める
- **進捗**: 読み込み中はウィンドウに進捗(読んだバイト数 / 全体)を表示する。読み込みはキャンセルできる(ウィンドウを閉じたら中断する)
- **問い合わせ**: ソート・フィルター・ページの要求ごとに、サーバが SQL を組み立てて実行する
  - クライアントから SQL を受け取らない。列は列番号で指定させ、サーバ側で列名を二重引用符で囲んでエスケープする。値はすべてパラメータとしてバインドする
  - 1ページ 500 行。表示範囲の前後1ページを先読みする
  - フィルター後の総行数も返す
  - 1回の問い合わせは 10 秒で打ち切る
- **資源の制限**: 共有サーバでの負荷を抑えるため、DuckDB のスレッド数は 2、メモリ上限は 1 GB にする(設定で変更可)
- **ファイルの更新時**: キャッシュを作り直してから、表示設定を保ったまま表示し直す

### 16.6 表示設定の一時保持

- 対象: ソート、フィルター、検索語、列幅、隠した列、固定した列、表示名、丸め、桁区切り、マーク、条件付き強調、文字コード・区切り文字・ヘッダーの手動設定、選択中のセル、スクロール位置
- ファイルの絶対パスごとに、サーバのメモリに保持する。タブを再読み込みしたり、同じファイルを開き直したりしたら元に戻す
- `dew stop` やサーバの再起動で消える(ディスクには保存しない)
- `R` ですべて初期状態に戻す
- マークは元の行番号(`__row`)で覚える。ファイルが更新されても、同じ行番号の行に付けたままにする

## 17. Markdown

### 17.1 描画の流れ

- サーバの `/api/text?path=` が UTF-8 に変換した本文を返す(15.8)。ブラウザ側で `react-markdown` を使って描画する
- プラグインの順番は次のとおり。`rehype-sanitize` は既定で id の先頭に `user-content-` を付けるため、`rehype-slug` はその後に置く(見出しへのリンク `#見出し` が正しく効くようにするため)

```ts
remarkPlugins: [remarkGfm, remarkMath, remarkFrontmatter]
rehypePlugins: [
  [rehypeSanitize, schema],   // 先に危険な要素・属性を除く
  rehypeSlug,                 // 見出しに id を付ける(目次・アンカー用)
  [rehypeKatex, { throwOnError: false, trust: false }],
  rehypeHighlight,            // コードの色分け(よく使う言語のみ同梱)
]
```

- `schema` は `rehype-sanitize` の既定スキーマを広げ、`remark-math` と色分けが使う class(`language-*`、`math-inline`、`math-display`)を `code` / `span` / `div` で許可したもの
- 生の HTML は描画しない(`rehype-raw` を使わない)。README によくある `<details>` や `<br>` も描画されないが、まずはこれでよいとする
- フロントマター(先頭の `---` で囲まれた YAML)は本文に出さず、ウィンドウ上部に折りたためる「メタデータ」として表示する
- 数式のエラーは、ページ全体を止めずに、その数式だけを MD3 の error 色の文字で表示する
- KaTeX の CSS とフォントは同梱する(CDN を使わない)
- Mermaid などの図の描画は対象外

### 17.2 リンク・画像の解決

`react-markdown` の `urlTransform` と、リンク・画像のコンポーネントの差し替えで、次のように処理する。

| 対象 | 処理 |
| --- | --- |
| 相対パスの画像 | Markdown ファイルの場所から解決し、認証付きの `/api/media?path=` で表示する(Cookie で認証)。閲覧範囲(`--root`)の外なら表示せず、「閲覧範囲外」と表示する |
| 外部の画像(`http(s)://`) | 既定では読み込まず、ドメイン名と「クリックで読み込む」を表示する。追跡や、オフライン時の待ち時間を避けるため。設定で常に読み込むようにもできる |
| `data:image/*` | 表示する |
| 相対パスの `.md` へのリンク | 同じウィンドウ内で移動する(ウィンドウ内の履歴に積む) |
| 相対パスのそのほかのファイル | dew の新しいウィンドウで開く(動画・画像・CSV など) |
| 相対パスのディレクトリ | Home でそのディレクトリを開く |
| `#見出し` | ページ内のその見出しまでスクロールする |
| 外部のリンク(`http(s)://`、`mailto:`) | ブラウザの新しいタブで開く(`rel="noopener noreferrer"`) |
| `javascript:` など、上記以外 | リンクにしない(文字だけ表示する) |

### 17.3 見た目

- 文字の大きさ・太さは MD3 のタイプスケールに合わせる(見出しは headline / title、本文は body)。本文の幅は最大 80 文字程度にして中央に置く
- コードは等幅フォントにし、色分けの色は MD3 のトークンに対応させる(ライト / ダーク両対応)
- 表は横にスクロールできるようにする。タスクリストのチェックボックスは操作できない表示だけにする
- 文字の大きさは `+` / `-` で変えられる(5段階)

### 17.4 キー操作(入力モード、vimium 風)

| キー | 動作 |
| --- | --- |
| j / k | 少し下 / 上にスクロール |
| d / u | 半画面 下 / 上 |
| gg / G | 先頭 / 末尾 |
| h / l | 左 / 右にスクロール(幅の広い表やコードがあるとき) |
| f | リンクヒントを表示し、文字を入力して開く(17.2 の処理)。画像へのリンクは、このウィンドウの中に画像を出す(`H` ですぐ戻れる気軽なプレビュー)。コードブロックのコピーボタンも選べ、選ぶとクリップボードにコピーする |
| F | リンクヒント。dew で開けるもの(画像を含む)は新しいウィンドウで開く |
| yf | リンクヒント。選んだリンクの URL(相対リンクはパス)をコピー |
| H / L | ウィンドウ内の履歴で戻る / 進む(スクロール位置も戻す) |
| / | ページ内検索。Enter で確定、`n` / `N` で次 / 前の一致へ |
| ] / [ | 次 / 前の見出しへ |
| o | 目次(見出しの一覧)を開く。`j` / `k` で選び、Enter で移動 |
| gu | この Markdown のディレクトリを Home で開く |
| yy | このファイルのパスをコピー |
| + / - / = | 文字を大きく / 小さく / 元に戻す |
| q / Ctrl+] | 15.3 のとおり |

**リンクヒントの細部**

- ヒントの文字はホームポジションの `a s d f g h j k l` の組み合わせにし、画面内のリンクだけに付ける
- 文字を入力するたびに、一致しないヒントを消していく。1つに絞れたら開く
- ヒントを表示している間は、ほかのキー操作を受け付けない。`Backspace` でヒントを閉じる(`Ctrl+]` は入力モードごと抜ける)。ヒントを出している間は、画面下のヒントの帯に抜け方を出す

**コードブロック**

- 右上にコピーボタンを置き、ワンクリックでブロックの中身をクリップボードにコピーする(2026-10-21 追加)

### 17.5 制限

- 5 MB を超える Markdown は、描画せずにプレーンテキストとして表示し、その旨を表示する
- 描画に 2 秒以上かかる場合は、読み込み中の表示を出す
