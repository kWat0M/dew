# 0016: ライブの一時停止・巻き戻しはブラウザが直近 30 秒の H.264 を持って行う

- 日付: 2026-10-18
- フェーズ: 4
- 状態: 採用

L7 の「直近 N 秒の一時停止・巻き戻し」(N は 9.1 の既定で 30 秒)は、ブラウザ側で行う。ブラウザはライブ映像として受け取った H.264 のフレームを、そのまま直近 30 秒ぶん(キーフレームの区切りで少し長め)持っておく(`web/src/canvas/liveRewind.ts`)。一時停止中やシークした位置の表示は、ライブとは別の VideoDecoder で、その位置の直前のキーフレームから復号し直して描き、再生は持っているフレームを実際の速さで復号して描く。持っている最後に追いつくとライブに戻る。サーバに巻き戻し用の API やバッファを持たせる案は、サーバとブラウザの間で位置を合わせる仕組みが要るうえ、同じフレームを2回送ることになるので採らなかった。ブラウザ側なら、すでに受け取ったものを使うだけで、遅延も増えない。メモリは 1080p でも数十 MB に収まる。キーは動画のウィンドウと同じ(`k`・Space で一時停止 / 再生、`j`/`l`・`J`/`L` で 5 秒・30 秒、`,`/`.` でコマ送り、`0`〜`9` でバッファの 0%〜90%)。下部のバーには一時停止ボタンを置き、ライブでない間はバッファのバー(ドラッグで移動)、何秒前か、「ライブへ戻る」を出す。一時停止中もアプリは動き続け、入力モードのキーもアプリに届く。キャンバスから Home へ戻るときに動画を止める決まり(7.6)は、ライブウィンドウには当てない。ウィンドウの大きさが変わって映像が作り直されたときは、前のフレームを新しい設定で復号できないので、持っていたフレームを捨てる。WebCodecs では flush の後はキーフレームからでないと復号を続けられないので、一時停止中の表示に flush を使い、再生を始めるときはキーフレームから復号し直す。
