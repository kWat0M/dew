# 0017: 精度モードは sitecustomize で cv2 を差し替え、PNG を Unix ソケットで送る

- 日付: 2026-10-18
- フェーズ: 4
- 状態: 採用

L3(`dew run --exact`)は、仕様 3.3 のとおり `PYTHONPATH` の先頭に同梱の `sitecustomize` を置いて実現する。フック(`python/dew_hooks/`)はバイナリに `include_str!` で入れ、実行のたびに `~/.cache/dew/python/` へ書き出す(中身が同じなら書き直さない)。もともとの `sitecustomize` は、`sys.path` の後ろから探して読み込む。cv2 は `sys.meta_path` のファインダーで import を捕まえ、読み込み終わった時点で `imshow`・`waitKey`・`waitKeyEx`・`pollKey`・`destroyWindow`・`destroyAllWindows`・`namedWindow` などを差し替える(OpenCV の `__init__` は途中で `sys.modules["cv2"]` を入れ替えるので、最後のものを直す)。差し替えた `imshow` は、配列を imshow と同じ見え方の 8bit(float は 0〜1 を 0〜255、16bit は上位 8bit)にしてから、アプリ側の `cv2.imencode` で可逆の PNG(圧縮レベル 1)にし、Unix ソケット(`DEW_EXACT_SOCKET`)で送る。生の画素を送る案は 1080p で 1 枚 6 MB になりブラウザまでの帯域が足りず、サーバで PNG にする案は png のクレートが要る。アプリの中の OpenCV で圧縮すれば依存は増えない。X のウィンドウは作らないので、画面の取り込みの映像と二重にならない。サーバ(`crates/capture/src/exact.rs`)は、窓の名前ごとに X のウィンドウ ID と重ならない ID(0x40000000 から)を振り、ライブウィンドウの一覧に `exact: true` で載せる。`/ws/live/{id}` は `LiveConfig.codec` を "png" にして PNG を送り、ブラウザは `createImageBitmap`(色の変換も premultiply もしない)で描く。これで画素が送った配列と一致する(受け入れ基準1。Chrome と Firefox で確かめた)。入力モードのキーは `waitKey` に返す(Enter・Esc・Backspace・Tab は OpenCV の GTK 版と同じ ASCII、ほかは文字のコードか X の keysym)。マウスのコールバック(`setMouseCallback`)は扱わない。キャンバスで閉じると `getWindowProperty(…, WND_PROP_VISIBLE)` が 0 を返すようにして、デスクトップで閉じたときと同じループの抜け方ができるようにした。精度モードの窓は録画・巻き戻しの対象外にする(PNG の列で、H.264 ではないため)。matplotlib は仕様どおり対象外で、ふつうのウィンドウの取り込みで表示される。
