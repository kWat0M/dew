# 0024: ドキュメントウィンドウと Markdown の実装で決めた細部

- 日付: 2026-10-21
- フェーズ: 6
- 状態: 採用

15・17章を作るにあたり、仕様にない細部を次のように決めた。(1) 文字コードの推定(15.8)で chardetng が日本語以外の文字コードを返したときも Shift_JIS として読む。手で選べるのは UTF-8 / Shift_JIS / EUC-JP だけで、判定を外したときは下部のメニューで直せばよいため。BOM のある UTF-16 は、そのまま UTF-16 として読む。(2) 描画のチャンク(`doc/MarkdownView.tsx`)には react-markdown・KaTeX・色分けと、その CSS だけを入れ、キー操作・リンクヒント・検索・目次・ファイルの監視は初期チャンクの `doc/DocumentWindow.tsx` が描画済みの DOM を相手に行う。キー操作を描画側に置くと、初めて開いたときにキーが効くまで待たされるため。Home のプレビューも同じチャンクを使う。(3) リンクヒントの文字は全部同じ長さにする(9 個までは 1 文字、81 個までは 2 文字)。途中まで打ったものが別のヒントと一致して先に開いてしまうのを避けるため。(4) 文字の大きさの5段階は、本文に CSS の `zoom` をかけて変える。MD3 のタイプスケールのトークンは px で決まっているので、トークンを使ったまま全体を拡大縮小するため。MD3 の headline のトークン(32/28/24px)は theme にまだなかったので、MD3 の標準の値で足した。(5) 最後の方の見出しも目次や `]` で上端まで送れるよう、本文の後ろに表示域の 70% の余白を置く。(6) 相対リンクの先がディレクトリかどうかは、`/api/tree` で開けるかどうかで決める(拡張子だけでは分からないため)。ファイルなら、親ディレクトリの一覧からその種類を読み、表示できない種類なら開かずに知らせる。(7) ページ内検索(`/`)は、一致した範囲を選択して見える位置へ送る。CSS Custom Highlight API はまだブラウザによって対応が違うので使わない。(8) ウィンドウの中で別の Markdown へ移ったら、タブとタイトルの名前もその文書にし、「同じファイルがすでにあればそのウィンドウへ」(15.2)の判定も今表示している文書で行う。(9) 目次は Radix の Popover、文字コードの切替は Radix の DropdownMenu で作り、目次の中の `Esc` は Radix ではなく dew のキー操作で扱う(Radix に閉じさせると、同じ `Esc` で入力モードまで抜けてしまうことがあるため)。(10) 外部の画像は、読み込むときも `referrerPolicy="no-referrer"` を付ける(どの文書から読んだかを外に送らないため)。(11) テスト用の Markdown は `tests/fixtures/md/` に作り、Home の一覧のテストに入らないよう、使うテストが閲覧範囲の起点の `md/` に複製する。CSV(フェーズ7)はまだファイルの種類に足していない。
