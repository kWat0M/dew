# 0022: 追加仕様(フェーズ5〜7)の統合と、実装に合わせた読み替え

- 日付: 2026-10-21
- フェーズ: 5〜7(仕様の統合)
- 状態: 採用

ユーザーがまとめた追加仕様(シェル連携、外部ツール連携、ドキュメントウィンドウ、CSV、Markdown)を spec に統合した。既存の章番号(「9 章のフェーズ」「11 章の受け入れ基準」など)は CLAUDE.md・ADR・コードのコメントから参照されているため、追加分は番号を変えずに済むよう末尾の 13〜17 章に置き、要件の表(3.1、3.2)、決定事項(9.1)、フェーズ(9 章)、受け入れ基準(11 章)には要点と参照だけを足した。追加仕様の「要確認」2件はユーザーに確かめて決めた: WezTerm の `user-var-changed` のハンドラは使う人だけが足す任意の設定とし(`dew setup-wezterm` は表示だけ)、人が確かめるときは、ふだんの `wezterm.lua` を変えずに `wezterm --config-file` でテスト用の設定のウィンドウを別に開く。DuckDB は `duckdb` クレート(bundled)で組み込み、今の配布方針(musl の静的バイナリ1つ)を保てる zig + `cargo zigbuild` をまず試し、通らないか遅いときに glibc 2.31 のビルドへ切り替える。開発用コンテナの rc ファイルへの `dew shell-init` の追記は、ユーザーが自分で行うので Dockerfile には書かない。実装と合わない前提は次のように読み替えた。(1) 追加仕様は再接続時に「既存の処理でウィンドウ配置を復元する」とするが、配置をサーバで持つ復元は未実装(9.2)。タブはページを読み直さずに `/ws/events` をつなぎ直すので、キャンバスのウィンドウはそのまま残る。これを要件とする。(2) `open_fallback_clipboard`、CSV の閾値、DuckDB の資源のようにサーバや CLI が読む設定は、9.1 で既定にしていた `~/.config/dew/config.toml`(まだない)を作って置き、ブラウザで決まる設定(`document_auto_input`、外部画像、通知)は今の localStorage の設定に足す。(3) フェーズ7の「小規模モードではサーバへの問い合わせが発生しない」は、表示のための `/api/csv/query` や行の取り直しが起きないことと読み、表示設定の保存(16.6 の PUT)は含めない。(4) 小規模と大規模で並び順を一致させるため、ソートの最後のキーに元の行番号を足し、同じ値の行の順を決める。あわせて、ユーザーの了承を得て、`--network host` で起動し直したときに開いていたタブのアドレスが変わらないよう、前回の待ち受けポートを保存して、空いていれば使い直すことにした(仮想ディスプレイ番号と同じ考え方)。`docker run -p` の形ではコンテナ内のポートは元から 8765 で変わらない。一度 8766 になると 8765 が空いても戻らないこと、止めている間に他の人がその番号を取れば結局変わることは承知のうえで採る。
