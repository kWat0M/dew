# 0021: git 管理外で $HOME の外なら、起動したディレクトリを閲覧範囲にする

- 日付: 2026-10-19
- フェーズ: 配布
- 状態: 採用(spec 7.2 の既定を変える)

ユーザーがサーバ上の自分のコンテナで試したところ、dew を起動すると閲覧範囲が `$HOME` になり、Home に「空のディレクトリです」としか出ず使えなかった。コンテナに root で入ると `$HOME` は空の `/root` で、見たいファイルは `/workspace` などの `$HOME` の外にあり、git 管理外(または `.git` がコンテナに入っていない)ことが多い。そのとき既定の範囲(git 管理外なら `$HOME`)は起動したディレクトリを含まず、Home の初期位置も範囲の起点(`/root`)になっていた。git 管理外で、起動したディレクトリが `$HOME` の外なら、起動したディレクトリを範囲にする(ユーザーの決定)。git リポジトリの中と `$HOME` の中で起動したときは今までどおりで、範囲を作業中の場所に限る考え(トークンが漏れたときの被害を小さくする)も保てる。あわせて、範囲が思ったのと違うときに気づけるよう、起動したとき(使い回すときも)と `dew status` で、閲覧範囲と変え方(`dew stop` の後 `--root`)を出す。範囲は server.json の `root` に書き、CLI はそれを読む(前の版のサーバは記録がないので出さない)。
