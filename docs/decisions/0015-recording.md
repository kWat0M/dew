# 0015: 録画は配っている H.264 を FLV にして ffmpeg で MP4 に詰め替え、キーフレームは1秒ごとにする

- 日付: 2026-10-18
- フェーズ: 4
- 状態: 採用

L7 の録画(`R`、MP4 で保存、再エンコードなし)は、ブラウザへ配っているのと同じ H.264 のフレームをサーバで受け取り、受け取った時刻を付けた FLV にして ffmpeg の標準入力へ流し、`-c copy -movflags +faststart` で MP4 に詰め替える(`crates/capture/src/record.rs`)。生の H.264(Annex B)には時刻がなく、ffmpeg に渡すとフレームレートから時刻を作るので、取りこぼしや揺らぎがあると長さがずれる。FLV は時刻(ミリ秒)を持てて、書き方が単純(ヘッダと、SPS・PPS の設定と、長さ付きの NAL を並べるだけ)なので、Rust 側で 100 行ほどで書け、新しいクレートも要らない。MP4 を Rust で直接書く案は、箱の種類が多く手間なので採らなかった。H.264 はキーフレームからしか再生を始められないので、録画は R を押した時刻に近いキーフレームから始める(直前のキーフレームが間隔の半分より新しければそこから、古ければ次のキーフレームから)。受け入れ基準「長さが録画時間と ±1 秒以内」を確実に満たすため、ライブ映像のキーフレームの間隔を2秒(9.1 の既定)から1秒に縮めた。ずれは最大 0.5 秒になる(実測で -0.4〜+0.45 秒)。キーフレームが増えるぶん映像の量は少し増えるが、1080p60 の性能の基準は満たしたままで、途中からつないだブラウザがすぐ映せる、巻き戻しのシークが速くなるという利点もある。保存先は最初に dew を起動したディレクトリの `dew-recordings/`(9.1)で、ファイル名は `<ウィンドウ名>-<UTC の時刻>.mp4`。録画中にウィンドウの大きさが変わったりアプリが閉じたりして映像が作り直されたときは、そこで録画を終える(途中で解像度の変わる MP4 は再生できないプレイヤーが多いため)。
