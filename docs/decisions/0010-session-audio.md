# 0010: ライブ描画の音声は、まずセッション全体で1本にする

- 日付: 2026-10-16
- フェーズ: 3
- 状態: ウィンドウごとの切り分けは 0013 で実装(セッション音声は、どのウィンドウにも結びつかない音の受け皿として残る)

仕様 7.6 では、PulseAudio のストリームのプロセス ID とウィンドウの `_NET_WM_PID` を突き合わせて音をウィンドウごとに結びつけ、結びつけられない音を「セッション音声」として扱う。フェーズ3では、仮想の出力先(null-sink)の音をまとめて1本の Opus にして送り(`/ws/live-audio`)、ウィンドウごとの切り分けは行わない。ウィンドウごとに分けるには、アプリごとに出力先を分けて取り込む仕組み(ストリームの移動と、出力先ごとの ffmpeg)が要り、受け入れ基準(440 Hz の検出)にも要らないため後回しにした。ウィンドウの PID は監視の段階で取っておく(`WindowInfo.pid`)ので、後から結びつけられる。音は全体のミュート(`M`)とキャンバスの表示に従い、ウィンドウごとのミュートはライブウィンドウには効かない。遅延を抑えるため、Opus は 10 ms 単位で区切り、Ogg のページもすぐ書き出す(`-page_duration`)。ブラウザでは 50 ms 先に予約して鳴らし、予約が 0.3 秒を超えて先に積み上がったら詰め直す。
