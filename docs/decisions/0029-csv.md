# 0029: CSV(フェーズ7)の作り方と、仕様にない細部

- 日付: 2026-10-23
- フェーズ: 7
- 状態: 採用

DuckDB は spec 9.1 の第一案どおり、`duckdb` クレート(1.20000.0、bundled)を zig 0.14.1 + `cargo zigbuild` で musl に静的リンクした。試したところ、DuckDB だけのプログラムで 3 分でビルドでき、100万行の読み込み 0.5 秒・ソートとフィルター 40 ms 以下だったので、glibc 2.31 への切り替えは要らなかった。DuckDB を入れた dew 全体の配布用バイナリは 57 MB。開発ビルドで DuckDB を最適化しないと遅すぎるので、`Cargo.toml` で `libduckdb-sys` だけ `opt-level = 3` にした。zig と cargo-zigbuild は開発用コンテナの Dockerfile に足し、`scripts/release.sh` は `cargo zigbuild` でビルドする。表の状態は、8月に安定版になった TanStack Table 9(9.3.1)で持つ。v8 は書き方を知っているが、これから作るものに一つ前の版を使う理由がないため。解析は小規模・大規模で同じもの(`crates/server/src/csv/parse.rs`)を使い、大規模モードでは1回目に列数・不揃いな行・型を数え、2回目に DuckDB へ流し込む。そのため、型の推定は spec 16.2 の「大規模モードは先頭 1,000 行」ではなく、両モードとも全行で行う。先頭だけで決めると、後ろの行に合わない値があったときに大規模モードだけ値を失い、両モードの結果がずれるため。100万行(97 MB)の読み込みは、2回読んで合わせて約 8 秒かかる(進捗を出す。2回目からはキャッシュを開くだけ)。DuckDB のテーブルの列名は dew が付けた `c0`, `c1`, …(元の値の文字列)と `n0`, …(数値・真偽値の列の型付きの値)にした。利用者の列名を SQL に入れないので、spec 16.5 の「列名を二重引用符で囲んでエスケープする」より安全で、表示・検索・`y` のコピーは元の文字列のまま両モードでそろう。値はすべて `$N` のパラメータで渡し、設定ファイルのメモリの上限も「数字 + 単位」の形だけを受け付ける。両モードで並び順をそろえるため、比べ方を1か所ずつに書いた(`web/src/csv/compare.ts` と `crates/server/src/csv/sql.rs`): 数値・真偽値は値(false < true)、日付は ISO 8601 の文字列のまま、文字列は小文字にしてコードポイント順(JS の `<` は UTF-16 の順なので使わない。DuckDB の VARCHAR の比較は UTF-8 のバイト順で、コードポイント順と同じ)。null は昇順・降順とも末尾で、同じ値の行は元の行番号の順(TanStack Table の `sortUndefined: 'last'` と、行の位置による最後の比較がちょうどこれに当たる)。条件の値が比べられない(数値の列に数値でない値)ときは、ブラウザでは適用せずに知らせ、サーバは 400 を返す。丸めの「そのまま」は、列の小数の桁数の最大とみなし、`-` で1桁ずつ減らす(6桁の列なら 5、4、…)。Home のプレビュー(15.5)は、大きなファイルを選んだだけでデータベースへの読み込みが始まらないよう、先頭 256 KB だけを読む `GET /api/csv/preview` を足した。ほかに spec 16.8 にない API として、検索(`POST /api/csv/search`。並べ替え・フィルター後の位置と列を、10万件まで返す)、行番号の位置(`POST /api/csv/locate`。`:` 行番号)、読み込みの中断(`POST /api/csv/cancel`)を足した。読み込みの進捗は、2回読む分を合わせて「読んだバイト数 / ファイルの大きさの2倍」で送る。データベースは `~/.cache/dew/csv/` に、元ファイルのパス・大きさ・更新時刻と読み方の手動設定から名前を決めて置き、変換のキャッシュと合わせて 5 GB を超えたら古いものから消す(開いているものは残す)。表示設定(16.6)は変えるたびにすぐ `PUT` で送り(`keepalive` を付け、変えた直後にタブを読み直しても届くように)、サーバのメモリに置く。マウスだけでも全操作ができるよう、列の見出しにメニュー(並べ替え・フィルター・表示名・隠す・固定・列幅・小数の桁)を付け、操作パネルにはフォーカス中の CSV の節を足した。フィルターなどの小さな画面は、右から出る操作パネルに隠れないよう、ウィンドウの左に出す。閾値と DuckDB の資源の設定は、`config.toml` の一番上に `csv_small_max_bytes`・`csv_small_max_rows`・`duckdb_threads`・`duckdb_memory` として置く(spec の名前のまま)。
