# 0013: ライブ描画の音は、pulseaudio 本体の CLI モジュールでアプリごとの出力先へ振り分ける

- 日付: 2026-10-17
- フェーズ: 3
- 状態: 採用

仕様 7.6 のウィンドウごとの音(ADR 0010 で後回しにしたもの)を、次のように作った。セッションの pulseaudio に、本体に入っている `module-cli-protocol-unix` を読み込ませ、dew はそのソケットへ pacmd と同じ文字のコマンド(`list-sink-inputs`、`load-module module-null-sink`、`move-sink-input`、`unload-module`)を送る(`crates/capture/src/pulse.rs`)。応答には終わりの印がないので、コマンドの後に知らないコマンドを1つ送り、そのエラーを応答の終わりとして読む。`pactl` を使えば楽だが、pulseaudio-utils という実行時の依存が増える(仕様 7.10 の依存は ffmpeg・Xvfb・pulseaudio)。Rust の pulseaudio のクライアントのクレートも、ストリームの移動に対応しているかが不確かで、バイナリも大きくなるので採らなかった。振り分けは 250 ms ごとのポーリングで、音のストリームの `application.process.id` が、ライブウィンドウの `_NET_WM_PID` そのものかその子孫(`/proc` の親をたどる)なら、そのアプリ用の出力先 `dew_p<PID>` へ移し、その monitor を ffmpeg で Opus にして `/ws/live-audio/{window}` で配る。音はウィンドウではなくアプリ(PID)ごとに持ち、同じアプリのウィンドウは同じ音を共有する(2つの窓を開くアプリで、どちらにフォーカスしても音が出るように)。結びつかない音は既定の出力先 `dew` のまま、セッション音声として今までどおり配る。ブラウザでは、ライブウィンドウの音を動画のウィンドウと同じ決まり(フォーカス中だけ、全体のミュート、同期再生中の設定)で鳴らし、セッション音声は全体のミュート以外では止めない。テスト用の周波数の測定は、音量をかけた後で行うように変え、鳴っていない音が測られないようにした。アプリの音が鳴り始めてから振り分けまで最大 250 ms ほどはセッション音声として鳴る。
