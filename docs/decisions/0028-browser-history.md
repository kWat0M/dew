# 0028: 画面の移り変わりをブラウザの履歴に積む

- 日付: 2026-10-23
- フェーズ: 6 の後(フェーズ7の前の修正)
- 状態: 採用

ユーザーの依頼を受けて、Home のディレクトリ移動・Home とキャンバスの切り替え・ドキュメントウィンドウ内のリンク移動を History API(`pushState` / `popstate`)でブラウザの履歴に積み、ブラウザの戻る・進むとマウスのサイドボタンで辿れるようにした(spec 4.5)。それまでは画面を React の state だけで切り替えていたので、戻るでページごと dew を離れてしまい、ドキュメントウィンドウではそれを避けるためにサイドボタンを `preventDefault` で止めてウィンドウ内の履歴を移していた(ADR 0026)。その止める処理は消した。文書の戻る・進むのボタンも、ユーザーの指示でブラウザの戻る・進む(`history.back()` / `forward()`)と同じにした。`H` / `L` も同じにしたのは、マウスでもキーでも同じことができるという方針に合わせるため。そのため、ウィンドウ内の最初の文書で戻ると、文書を開く前の Home へ戻る。ボタンが有効かどうかは、このタブで dew の中を動いた分(履歴の項目に持たせた通し番号)で決め、dew より前のページへは戻らないようにした。URL は `/`(初期位置)・`/home/<パス>`・`/canvas` にした。ハッシュ(`#`)ではなくパスにしたのは、サーバがすでに知らないパスに `index.html` を返しており、トークンを Cookie へ移すリダイレクトもパスを保つので、サーバを変えずに済み、URL も読みやすいため。履歴の項目には、画面・ディレクトリ・フォーカス中のウィンドウ・文書の番号を持たせる。ウィンドウの番号はページを読み込むたびに振り直すので、項目に読み込みの印を付け、再読み込み前の項目ではウィンドウを指す部分を使わない(キャンバスのウィンドウを再読み込みで戻すのは、7.7 の未実装の項目のまま)。ドキュメントウィンドウは、移った文書の並びを自分で持ち、どれを出すかは履歴が決める番号に従う。スクロール位置は文書の番号ごとにスクロールのたびに覚え、番号が変わった描画の直後に戻す位置を決める(読み込みを待つ間に位置が 0 に縮むため)。カーソルの移動・ウィンドウのフォーカス・絞り込みは積まない(履歴が細かくなりすぎ、戻るの1回で戻る量が分かりにくくなるため)。キャンバスの中でファイルを開いても積まないのは、戻ってもフォーカスが変わるだけで、見た目にほとんど変化がないため。パンくずは `<a href>` のリンクにして、中クリックなどではブラウザの新しいタブでそのディレクトリを開けるようにした(ふつうのクリックは今のタブの中で移る)。下部のバーの戻る・進むは、左端では押しにくいとの指摘を受けて、バーを3列のグリッドにして中央に置き、ほかより大きくした(36px、アイコン 24px)。
