# 0023: シェル連携・外部ツール連携の実装で決めた細部

- 日付: 2026-10-21
- フェーズ: 5
- 状態: 採用

13・14章を作るにあたり、仕様にない細部を次のように決めた。(1) 仮想ディスプレイ番号は「server.json に保存」とあるが、server.json は `dew stop` で消えるため、前回のポートと一緒に `~/.local/share/dew/state.json` に置いた。トークンは仕様どおり `~/.local/share/dew/token`(権限 600)。Cookie 名に使うインスタンス ID も state.json に保存して使い直す(毎回作り直すと、同じトークンでも再起動後のタブの Cookie が通らず、自動再接続が成り立たないため)。(2) 前回のポートは、`--port` / `DEW_PORT` の指定がなく、かつ `DEW_PUBLIC_PORT` もないときだけ試す。`docker run -p` の形で公開しているのはコンテナ内の 8765 なので、別の番号を使い直すと外から届かなくなるため。(3) activate 中のシェルの点検は、仕様の「1分ごと」より短い 10 秒ごとにした。/proc を読むだけで軽く、端末を閉じてから登録が消えるまでを早められる(受け入れ基準の「1分以内」も満たしやすい)。`dew status` と `dew stop` が数を問い合わせたときにも、その場で点検する。(4) activate の元の値の保存は、dew が出したコードをシェルの中で実行して行う(`_DEW_SAVED_<名前>` は export する)。export していない変数は子の dew から見えないため。deactivate は、環境に残っている `_DEW_SAVED_*` から戻すコードを出す。プロンプトの元の値は export しない `_DEW_PROMPT` に置く。すでに activate 中のときは、サーバへの登録もし直さない(「何もしない」を文字どおりに取った)。(5) `/open?path=` は、指定のファイルを予約(14.4 と同じ仕組み)してから `/` へ移すだけにした。開いたタブは `/ws/events` につないだときに予約を受け取って開くので、画面側に別の入口を作らずに済む。タブがないときに標準エラー出力に出す URL もこの `/open?path=…&token=…` にし、手で開いてもそのファイルが開くようにした(以前は Home の URL を標準出力に出していた)。(6) `dew rotate-token` は、動いているサーバのトークンをその場で差し替え、`/ws/events` の接続をすべて切る。切れたタブは「サーバ停止中」を出して再接続を試み続け、古いトークンでは通らない。(7) 設定ファイル `~/.config/dew/config.toml` は CLI が読む `open_fallback_clipboard` だけで作り始め、知らない項目は読み飛ばす(後のフェーズの設定を同じファイルに足せるように)。読むのに `toml` クレートを足した(ユーザーの了承済み)。(8) E2E で「裏にあるタブ」を確かめるとき、ヘッドレスのブラウザは別のタブを前に出しても元のタブを裏にしない(`visibilityState` が変わらない)ため、ページの `document.hidden` を差し替えて `visibilitychange` を送る。
