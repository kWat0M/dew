# 0009: ライブ描画の取り込みとエンコードは ffmpeg の CLI に任せる

- 日付: 2026-10-16
- フェーズ: 3
- 状態: 採用

仕様(6.3、9.1)ではライブ描画を「XComposite で取り出し、同梱の openh264 で H.264 にする」既定だったが、ウィンドウごとに ffmpeg を起動し、`x11grab -window_id` でそのウィンドウだけを取り込み、libx264(`-preset ultrafast -tune zerolatency`)で H.264 にする方式に変える。openh264 は C++ のライブラリで、配布用の musl 静的バイナリに組み込むには musl 向けの C++ ツールチェーンが要り、ビルドが重く壊れやすい。ffmpeg はすでに必須の依存で、x11grab・PulseAudio 入力・libx264・libopus・NVENC がそろっているため、NVENC への切り替え(L4 の後半)も同じ経路で済む。試作では、Xvfb 上の OpenCV のウィンドウを 640×420・60fps で取り込めた(奇数の幅・高さは 1 画素足して偶数にする)。X11 の監視(新しいウィンドウ、名前、大きさ)と入力の注入(XTest)は純 Rust の x11rb で行い、C のライブラリは足さない。代わりに、ウィンドウごとに ffmpeg のプロセスが1つ増え、生の画素をプロセス間で受け渡すぶん CPU を使う。重なったウィンドウの隠れた部分が欠けないよう、仮想ディスプレイ(3840×2160)の上でウィンドウが重ならない位置に dew が置き直す。
